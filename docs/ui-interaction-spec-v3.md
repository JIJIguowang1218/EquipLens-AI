## 1. 全局骨架

### 1.1 左栏

`clamp(200px,21vw,280px)`，**从页面最顶部开始**（y=0）：旧 logo（占位）+ `EquipLens` + `最近` 列表；≤760px 收成 56px 只留 logo。

### 1.2 顶部阶段进度（含步骤名）

五段等宽横线，**占满工作区宽度**（左栏右侧到视口右缘）。每段线下面是阶段名：

| 状态 | 横线 | 阶段名 |
|---|---|---|
| 已走过 | `rgba(242,241,238,.42)` | **显示**，`#6A6A66` 灰 |
| 当前 | `--paper` | **显示**，纸色高亮 |
| 未到达 | `rgba(242,241,238,.10)` | **不显示** |

- 阶段：`00 立项 / 01 检索 / 02 素材 / 03 排版 / 04 交付`
- **回退后，曾经走过的阶段仍按"已走过"灰显**（表示到达过），当前阶段高亮。
- 未到达的那格横线仍占位；靠 `min-height` 保证与已到达的对齐，不能比其它矮。

### 1.3 状态条

阶段条下方、内容区之上：左侧状态灯 + 状态词（检索中/检索完成/分析中/分析完成/排版中），中间当前上下文（`车型 · 图 n / N`、`第 n / N 页`），右侧计数与次级操作（重新检索/重新分析/撤销）。

### 1.4 底部动作坞（dock）

**位置**：只存在于中间工作区这一栏内，**不得侵入左栏和右栏**（宽度 = 内容列宽；1440 下 S2 为 304–1009，右栏从 1027 起）。贴住内容区底部，浮在内容之上（顶部 62% 渐变遮罩）。

**收起态（默认）是一行**：

```
[‹ 上一步] [元信息]        [主行动（居中）]        [输入框（占主行动右侧到列尾）]
```

| 位置 | 内容 |
|---|---|
| 左 | `‹ 上一步`（只读回看）；S3 另有 `12 页 · PPTX` |
| 中 | **主行动居中**：S1 `确认并开始分析`、S2 `确认并开始排版`、S3 `暂存` + `导出` |
| 右 | 常驻输入框（单行 34px，含发送键 `↑`），从主行动右侧延伸到列尾 |
| 无 | **没有独立的"提要求"按钮**——输入框本身就是入口 |

**展开态（点击/聚焦输入框）**：

- 输入框变成满宽大框（88–180px 自适应）；
- **主行动被顶上去并移到右侧**（左端留 `‹ 上一步`）；
- 两者之间出现一行 `系统预判：回到 <阶段> · 只重做 <对象>`；
- 上方内容自动让位（主图/卡片区收缩），不互相遮挡。

**输入框行为**

| 操作 | 行为 |
|---|---|
| 点击/聚焦 | 展开为大输入框 |
| Enter | 提交 |
| Shift+Enter | 换行 |
| 失焦且为空 | 自动收回单行 |
| 提交后 | 收起、清空，给出结果提示（toast） |

**硬规则**

- 预判**只说回到哪一步、影响哪个对象/范围**，**任何情况下不得显示耗时/预计时间**。
- **一次确认**：用户主动输入即视为明确意图，提交后直接生效，不弹二次计划确认。
- 不提供"手动指定回退到哪一层"；用户要改什么，自己翻到对应页面在输入框里说。
- 等待态（检索中/分析中）主行动置灰，但输入框仍可用。
- 同一时间只允许一个回退任务；执行中再提交 → 排队并提示。

### 1.5 视觉与字号

墨 `#0B0B0C`/`#121214`/`#17171A`；纸 `#F4F2ED`（纸上字 `#141414`）；正文 `#F2F1EE`、次级 `#9A9A95`、三级 `#6A6A66`；线 `.13` / `.07`。正文 13、辅助 11、标签 10（`letter-spacing:.13em` 大写）；**型号与数字一律等宽**（tabular-nums）。

### 1.6 响应式

≤1180 卡片 2 列；≤900 右栏堆叠到主区下方（不隐藏），dock 取消吸底；≤760 左栏收成 56px。

## 2. S0 立项台

**布局**：左栏（logo/名称/最近）＋ 主区居中：`今天看什么设备？`、副标题"输入设备类别，或者直接说一句话，剩下的交给我。"、单输入框＋`开始`、下方`＋ 上传图片（可选）`。

## 3. S1 检索台（`retrieving` → `ready`）

**布局**：状态条"检索中/检索完成"；左区**卡片网格每行 3 辆**；右区上＝关联分析散文、下＝清单横条；底部动作坞。

**卡片（一辆一张）**

| 元素 | 规格 |
|---|---|
| 主图 | 占位剪影；**单击或右键循环 1→2→3**，右下角计数 `1 / 3` |
| 关联程度 | 色点＋文字（精确类目/环境特化/基型平台/跨车型） |
| 基础信息 | 车型名（等宽）＋ `品牌 · 构型` |
| 选中 | 左上勾选框；已选＝纸底勾，未选＝空框 |
| 备选（多出的 2 台） | 保持图片与信息，但整体灰化、虚线描边、不勾选 |

**台数与滚动**：台数动态；**每行固定 3 辆**，超出时卡片区内部滚动，整页不滚。

**三种状态**（`?s=`）

| 参数 | 表现 |
|---|---|
| `?s=start` | 全部卡片灰色占位＋信息骨架、关联文本骨架、清单骨架、主行动禁用 |
| `?s=mid` | 已返回的卡片填充并选中，其余仍占位 |
| `?s=done`（默认） | 6 推荐选中 + 2 备选灰卡；文本与清单完整；主行动可用 |

**底部动作坞**：`‹ 上一步`（回看立项台，只读）｜`确认并开始分析`（居中）｜输入框。

**清单横条**：一台一横条，含名称、`构型 · 品牌`、层级标签、关联原因；层级用填充色 + 左侧 2px 色条，跨车型备选用虚线。

**层级配色（占位方案）**：单色透明度递进（纸白→暖灰→中灰→虚线）。**高保真必须改为用户一眼能懂的明示色并配图例**。

## 4. S2 素材与分析台（`analyzing` → `ready`）

### 4.1 布局

| 区域 | 内容 |
|---|---|
| 状态条 | 状态词（分析中/分析完成）＋ `车型 · 图 n / N` ＋ `k / 5 部件已框` ＋ 暂停/重新分析 |
| 主图卡 | 左右窄箭头（切车）；**画布拉伸到控件行上方，画布内嵌 16:9 照片**（letterbox）；图上叠加部件框 |
| 控件行 | `‹ 上一辆` ／ 中间 `‹ 图 1 / 3 ›` ／ `下一辆 ›`——车辆切换在两侧，图内切换在中间 |
| 胶片条 | 横向缩略卡展示全部车辆与当前位置（`车辆 3 / 8`）；当前项纸色描边；备选灰化虚线；可点击跳转；紧贴动作坞上方 |
| 右栏 | `部件分析 k / 5 已框`；一个部件一横条（见 4.2）；无额外常驻提示 |
| 底部动作坞 | `‹ 上一步`｜`确认并开始排版`（居中）｜输入框 |

### 4.2 部件行内容（必须按分析 schema，不得写成泛泛一句）

字段取自 `docs/superpowers/specs/2026-10-31-analysis-schema-design.md` §2.2，槽位与构型名取自 `data/part_taxonomy.json`：

| 行内元素 | 来源字段 | 说明 |
|---|---|---|
| `01` 序号 | — | 两位等宽，与图上框的编号一致 |
| 部件名 | 槽位 `label` | 进气格栅 / 保险杠 / 翼子板与轮拱 / 登车踏步 / 侧防护栏 |
| 构型名 | `term` | **必须命中词表**（横置多层格栅 / 整体式保险杠 / 方形轮拱 / 两级固定踏板 / 型钢侧防护栏）；命中不了则 `term=null` |
| CMF | `cmf.material_class · cmf.finish` | 如"钢板 · 哑黑喷涂" |
| 族 | `part_family` | 钣金件 / 型材框架 / 铸锻件 / 功能件 |
| 形态 | `form` | **≤2 句**，写可见的构造与分缝，不写评价 |
| 意图 | `intent` | **≤1 句**，因果最多两级，写"为什么这样设计" |
| 状态标签 | 见 4.3 | 已框定 / 本图可见·待框选 / 在 图 N 框选 / 本图不可见·换图后框 |

**文风**（同文件 §5）：一句一个判断、≤30 字、禁框架句（"由……构成""通过……实现""呈现出"）、术语不解释、数字可估读才给并标（估）、禁空评价（"大气""很有质感"）。
**可见性诚实**：`visible=not_visible` 时不得输出构型名与描述（不许用常识补全），只显示"本图不可见·换图后框"。

### 4.3 部件行四态

| 状态 | 含义 | 标签写法 |
|---|---|---|
| `framed` | 当前图已有框 | `已框定` |
| `pending` | 本图可见但尚未框 | `本图可见 · 待框选` |
| `elsewhere` | 同一辆车的另一张图上已框 | `在 图 N 框选`（点击直接跳到那张图并选中） |
| `hidden` | 本图看不到该部件 | `本图不可见 · 换图后框` |

### 4.4 框选与联动

- **点行 → 图上高亮**：该框纸色 1.5px 描边 + 四角手柄 + 实心标签；其余框保持虚线。
- **点框 → 右侧同步**：对应部件行高亮（纸色左边框 + 深底）。
- **新建框**：先选中"待框选"部件，再在图内拖拽；拖动距离小于 3% 视为误触，不落框。
- **调整框**：拖动已有框移动位置（缩放留到高保真）。
- **换图框选**：图上看不到的部件 → 切到下一张 → 点该部件 → 拖框；**其他部件在原图上的框保留**（归属 = 车 × 图 × 部件）。
- 图内浮层提示：选中待框选部件时显示"在图上拖动，为「X」框选"；选中不可见部件时提示"本图看不到「X」，可切换图片后再框"。该提示只出现在图上，**右栏底部不再有常驻提示**。

### 4.5 状态

| 参数 | 表现 |
|---|---|
| `?s=done`（默认） | 框已就位、五行完整、主行动可用 |
| `?s=working` | 无框、右侧骨架行、状态条 `分析中 · 2 / 5 部件`、主行动禁用 |

## 5. S3 排版与导出（`composing` → `ready`）

### 5.1 布局

| 区域 | 内容 |
|---|---|
| 状态条 | `排版中` ＋ `车型 · 第 n / N 页` ＋ `16:9 · 选中 主图` ＋ `撤销` |
| 左·单页画布 | 16:9 纸色页面；块可点选、可拖动；选中显示 1.5px 墨色框＋四角手柄；**选中对象名只在状态条显示**，页面上不浮标签 |
| 右·页面预览 | 竖向缩略图列表（对应 PPT 幻灯片栏），当前页纸色描边、点击跳页；缩略图按类型区分（封面/方法/车型页/总览/封底） |
| 底部动作坞 | `‹ 上一步` + `12 页 · PPTX`｜`暂存` + `导出`（居中）｜输入框 |

### 5.2 页面结构（一车一页）

标题（车型＋构型）/ 风格词（三个，来自 `style_vocabulary.json`）/ 主图 / 2×2 部件裁图（构型名＋CMF，即 S2 已确认的部件）/ 前脸分析（`region`：gesture＋2–3 条特征线＋比例估）/ 页脚（页码、来源、日期）。

页面类型：`封面` / `方法与来源` / `车型页`（× N）/ `竞品总览`（8 台索引）/ `封底`。默认 12 页 = 封面 + 方法 + 8 车型 + 总览 + 封底。

### 5.3 编辑

- 点块选中；拖动移动（百分比定位）。
- 撤销：占位（高保真接历史栈）。
- 选中态不改变页面内容，只画编辑框，避免影响成品观感。

### 5.4 导出与暂存

| 动作 | 行为 |
|---|---|
| 导出 | 优先 `showSaveFilePicker()` 打开**系统保存对话框**，默认文件名 `EquipLens-沙漠牵引车-竞品分析-<日期>.pptx`；用户取消则不写文件；接口不可用或被拒（如内嵌视图）→ 浏览器下载兜底并提示 |
| 暂存 | 写 `localStorage` 草稿 ＋ 提示"已暂存到本地草稿" |

> 静态稿导出的是占位文件（mock）；真实 PPTX 由排版 IR 确定性渲染，属后续模块。

## 6. 回看、提要求与回退

### 6.1 三种语义（别混）

| 语义 | 入口 | 是否重算 |
|---|---|---|
| **回看** | 动作坞 `‹ 上一步`、顶部已走过的阶段 | **否**，只读导航，状态保留，可前进回来 |
| **局部重做** | 输入框提要求 → 系统判定最小范围 | 是，只重算受影响对象 |
| **跨步重算** | 输入框提要求 → 系统判定回到更早阶段 | 是，影响面较大，下游标 stale |

**没有"全局回退上一步"主按钮**：一个按钮无法表达"看看 / 改一处 / 重跑整批"三种代价，容易误触昂贵重算，所以回看与重做分开。

### 6.2 提要求规则

- 用户在**常驻输入框**里写要求，提交即生效（**一次确认**，不弹二次计划）。
- 系统在提交前给出**预判**：回到哪个阶段、影响哪个对象/范围；**只说步骤，不说时间**。
- 预判随输入实时更新；要改别的对象，用户自己翻到对应页面再说（不提供"手动指定回退层"）。
- 提交后给出结果提示（toast），如 `已提交：回到「检索」重做 德龙 X3000`。

### 6.3 系统回退判定（回到"产生这个错误的最早一层"）

| 用户说法（例） | 错误所属层 | 回到 | 重算范围 | 保留 |
|---|---|---|---|---|
| 这台不是 X3000 / 图不相关 | 检索·识别 | S1 检索 | 该车 1 台 | 其他车与已勾选清单 |
| 换一张主图 / 这张不好看 | 素材 | S2 选图 | 该车该页 | 部件框（换图后框需复核） |
| 轮眉框错了 / 看不到这个部件 | 框选 | S2 框选 | 该车该部件 | 其余部件框 |
| 这段分析太啰嗦 / 说错了 | 文本 | S2 分析（或 S3 直接改） | 该部件 | 其余内容 |
| 这页排得太挤 | 版式 | S3 | 该页 | 内容不变 |
| 清单少了一台竞品 | 清单 | S1 清单 | 清单 → 下游页 | 已确认内容标 stale |
| 整体方向错了（不是沙漠工况） | 需求 | S0 | 全量 | 无（需明确提示清空） |

### 6.4 回退后的结果处理

- **回退不删成果**：下游结果保留但标 `stale`（灰显 + "待更新"），前进时提示"3 处已过期，是否重算"。
- 每次提要求落一条台账：对象、原话、系统判定、实际回退点、最终是否满意——用于调规则与回归。

## 7. 跳转与状态机

```
S0 立项 ──提交──▶ S1 检索（retrieving → ready） ──确认并开始分析──▶ S2 素材（analyzing → ready）
       ──确认并开始排版──▶ S3 排版（composing → ready） ──导出──▶ 文件
```

- 等待态（`retrieving` / `analyzing` / `composing`）**不单独成页**，是同路由的整屏 morph（对象、主动作、空间模型三者都变才算新界面）。
- 取消：S1 检索中 → 回 S0；S2 分析中 → 回 S1 且保留已确认清单。
- 重新检索：保留已勾选项（需二次确认）。
- 回看不改变下游状态；回退只由输入框发起，规则见 §6。

## 12. 12 栏栅格（v4 版式，2026-11-05 定稿）

v3 的 `s0–s3.html` 是流式布局（`clamp()` 连续变化、右栏三套宽度），没有栅格。v4 起按本节实现，**新文件在 `docs/ui-mock/v4/`，v3 原文件保留作对照**。

### 12.1 左栏不参与栅格

左栏是 **rail**（固定槽），12 栏只落在内容区。这是主流做法：Carbon 的左导航、Ant Design 的 `Sider` 都在内容栅格之外，只有 `Content` 内部才有栏。

- rail 宽 `clamp(200px, 21vw, 280px)`，与内容区以 1px 分隔线相接；
- rail 内部的文字起点必须与内容区的外边距对齐（同一套 `--margin`）。

### 12.2 一套令牌，三页共用

```css
--rail:   clamp(200px, 21vw, 280px);   /* 左栏（栅格外） */
--margin: clamp(16px, 1.7vw, 24px);    /* 内容区左右外边距 */
--gutter: 16px;                        /* 栏间隙，同时是卡片间隙 */
--pad-y:  16px;                        /* 内容区上边距（8pt 节奏） */
```

1440 宽时：内容区 1160，`12×78 + 11×16 + 2×24` 正好成立，但**不能依赖它**——栏宽由 `repeat(12, minmax(0,1fr))` 自动算，任何宽度都成立。

### 12.3 分栏

| 界面 | 内容区（1–8 栏） | 右栏（9–12 栏） |
|---|---|---|
| S0 | `.ask` 占 1–8 栏 | 空 |
| S1 | 卡片区 1–8 栏 | 分析＋清单 9–12 栏 |
| S2 | 画布＋胶片条 1–8 栏 | 部件行 9–12 栏 |
| S3 | 单页画布 1–8 栏 | 页面预览 9–12 栏 |

**三页右栏宽度必须一致**（8/4 分栏），分界线才不会在换阶段时跳。v3 里 S1/S2/S3 的右栏分别是 `23vw`/`27vw`/`17vw`，分界线相差 57–159px，这是要修的主要问题。

### 12.4 每行 3 辆 = 嵌套栅格

8 栏里放 3 张卡，用**嵌套栅格**（Bootstrap 的 `.row`/`.col` 同一思路），不是让每张卡占整数栏：

```css
.cards-col{grid-column:1 / span 8}
.grid{display:grid;grid-template-columns:repeat(3,minmax(0,1fr));gap:var(--gutter)}
```

- 卡片区的左右边缘落在栏线上（第 8 栏终点），内部三张卡不必对齐栏线；
- 卡片间 `gap` 必须等于 `--gutter`（16），v3 用的是 12，与栏间隙不一致；
- 若强行让每张卡占 4 栏（共 12 栏），右栏就没有位置了——这是 v3 塞不进栅格的根因。

### 12.5 进度条也压栏线

5 段按 **2 / 2 / 3 / 3 / 2** 栏分配，段边界正好落在栏线上（`grid-column: span 2`，第 3、4 段 `span 3`）。v3 是 `flex:1` 五等分，段边界与栏线无关。

### 12.6 断点

| 宽度 | 行为 |
|---|---|
| ≥ 1180 | 12 栏；卡片每行 3 辆；右栏 4 栏 |
| 900–1180 | 12 栏不变；卡片每行 2 辆（栏数不变，只改嵌套列数） |
| < 900 | 单列堆叠：右栏移到下方，`grid-column: 1 / -1` |
| < 760 | rail 收成 56px 图标条 |

换断点改的是**占栏数与嵌套列数**，不重写 `grid-template-columns` 的栏数。

### 12.7 为什么选 8 / 4

S2 的部件行要在一行里装 `term / family / form / cmf / intent` 五个字段，右栏最需要宽度；S1 的关联散文也需要 ≥ 320px 才不碎。9/3 方案（每卡正好 3 栏）会让右栏只剩 266px，部件行会挤成两段。3 辆/行用嵌套栅格即可保住，所以选 8/4。
