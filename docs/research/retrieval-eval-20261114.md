# 无标注/弱标注下的检索评估 与 query expansion 失败模式

调研日期 2026-11-14。只做网络检索，未读本地数据、未改代码。
适用对象：EquipLens 两段式检索（文本候选发现 → 图片抓取核验）。
先给结论：**没有 qrels 也能评，但必须先冻结"评什么、在哪判"**；LLM 可以替代大部分人工判断，替代不了"定义相关性"这一步。

## 方法与证据

### 1. Pooling + 判断深度 + 不完全判断下的稳健指标
- 来源：[Buckley & Voorhees 2004](https://doi.org/10.1145/1008992.1009000)（bpref）、[Lu, Moffat & Culpepper 2016](https://doi.org/10.1007/s10791-016-9282-6)（池深度影响指标）、[Sakai & Kando 2008](https://link.springer.com/content/pdf/10.1007/s10791-008-9059-7.pdf)（Q′/nDCG′/AP′）、[HC4](https://arxiv.org/abs/2201.09992)（用 active learning 补池子漏洞）、[TREC 2024 Overview](https://trec.nist.gov/pubs/trec33/papers/overview_33.pdf)（PDF，仅确认链接，正文未逐字核对）。
- 怎么做：把 N 个系统（当前版/上一版/一个弱基线）的 top-k 合并去重成 pool，只判 pool 内的文档，记录池深度与 judged 覆盖率。Lu 等证明池越浅指标越偏、甚至改变系统排序，所以池深度必须跨版本固定。未判文档一律按"非相关"会系统性惩罚没参与 pooling 的系统，可改用 Q′/nDCG′/bpref 这类对不完整判断更稳的指标；HC4 则说明老池子是按老系统建的，新范式会有系统性盲区，需要补池或重建。
- 用在我们：**候选召回**（建第一份标准集）+ 排序指标的稳定性
- 成本：人工判 pool 是大头（约 1 分钟/对），200 query × 深度 20 ≈ 数千对｜局限：池外好结果永远算 0 分；池深度一变历史数字不可比。

### 2. BEIR 式固定协议：可比性来自"冻结"，不是来自"多"
- 来源：[BEIR](https://arxiv.org/abs/2104.08663)
- 怎么做：固定 corpus + 固定 query 集 + 固定 qrels + 单一主指标 nDCG@10，所有系统在同一份判断上比。BEIR 用 18 个异构集说明"单集提升 ≠ 泛化"，并指出多数判断由词法系统参与构建、存在 lexical bias：人工补判未判文档后，非词法系统明显上升。
- 用在我们：**排序**的跨版本回归；我们缺的不是指标，是一份不随改动变化的快照集。
- 成本：一次性建设，之后近零｜局限：只回答"在这份集上谁更好"，不回答线上分布漂移，也不能替代本域数据。

### 3. LLM 当评审员：1SL 单例标注 / UMBRELA 规模化 / 补洞
- 来源：[1SL](https://arxiv.org/abs/2302.11266)、[UMBRELA + TREC 2024 RAG 大规模对比](https://arxiv.org/abs/2411.08275)、[LLM 补洞](https://arxiv.org/abs/2405.04727)
- 怎么做：给 query + 候选（+ 一个已知正例）让 LLM 打 0–3 分，再用它填未判文档。UMBRELA 在 TREC 2024 RAG 用 77 个 run 对比人工：nDCG@20/100、Recall@100 的系统排序相关性很高，且"人工+LLM 混合"并不比纯自动更相关（人工评审更严）。补洞实验显示只保留 10% 判断时，LLM 补洞后系统排序的 Kendall τ 仍有 0.87–0.92。关键：1SL 逐条标签常与人不一致，但**系统级排序**可靠——所以它适合判"A 版 vs B 版"，不适合做"这条对不对"的终审。
- 用在我们：**排序** + **抓图命中率**（把"图是否可用"当判断项，用多模态模型判）
- 成本：千对级约几元到几十元 API 费 + 一次性校准｜局限：位置/长度/自我偏好偏差；必须用人工小样本校准并报告一致性（κ 或排序相关），否则只是换了个偏见来源。

### 4. 合成 query 生成：从"有图/有记录"反推 query
- 来源：[InPars](https://arxiv.org/abs/2202.05144)、[Promptagator](https://arxiv.org/abs/2209.11755)、[InPars+](https://arxiv.org/abs/2508.13930)
- 怎么做：让 LLM 看一条文档/商品记录，生成"什么样的 query 会来找它"，得到 (合成 query, 正例) 对。Promptagator 用 8 个示例即可生成任务特定数据，11 个集上比 ColBERTv2 平均高 1.2 nDCG；InPars 生成 10 万条只留 1 万条（90% 被过滤），InPars+ 的结论是过滤很贵、可用偏好优化减少丢弃。
- 用在我们：**候选召回**——长尾车型/品牌没有真实 query，只能用车型库反生成，才谈得上"这个车型能不能被召回"。
- 成本：一次性生成 + 人工抽检 5%｜局限：合成 query 比真实用户更"标准"、更爱用官方术语，只能测覆盖，不能替代日志；必须记录 prompt 与模型版本才可复现。

### 5. 弱监督 / 数据编程：把规则回放升级成"带噪声模型的标签"
- 来源：[Snorkel](https://arxiv.org/abs/1711.10160)；"silver labels + 部分人工校验"的实践见 [KSE-Web](https://arxiv.org/abs/2608.21365)
- 怎么做：写多条互为补充的启发式规则（标题含车型、来源白名单、图片宽高比、URL 模式……），每条规则投票，用生成模型估计各规则准确率与相关性，在**无真值**下合成概率标签；Snorkel 报告专家建模比纯手标快 2.8×、效果高 45.5%。
- 用在我们：**候选召回**的弱标签 + **抓图命中率**的分层预筛（人工只抽边界层）
- 成本：写规则 1–2 人日，算力可忽略｜局限：规则间相关性会让置信度虚高；只对规则覆盖到的分布有效，长尾等于没标；能用来排优先级，不能用来证明"改好了"。

### 6. QPP：不用任何标注的质量预检
- 来源：[QPP for Neural IR: Are We There Yet?](https://arxiv.org/abs/2302.09947)
- 怎么做：用 query 本身与结果集特征（歧义度、top-k 分数分布、结果间相似度、分数间隔）预测这次检索好不好，不需要人工判断。该文用 19 个 QPP 测 14 个系统，发现 QPP 在神经/语义系统上显著变差（最多降 10%），且在"新旧系统差异最大"的 query 上失效。
- 用在我们：**全链路哨兵**——改动后先看 QPP 分布是否整体位移，作为"要不要跑昂贵评估"的触发条件，并定位变差的 query。
- 成本：极低（纯计算）｜局限：只能相对比较、不能给绝对好坏；中文工程术语 + 短 query 场景下其相关性**未验证**，必须先在小样本上与人工判断做一次相关性检验再信。

### 7. Query expansion / multi-query 的失败模式：query drift
- 来源：[ReformIR (SIGIR'26)](https://arxiv.org/abs/2605.00560)、[KSE-Web 低资源实证](https://arxiv.org/abs/2608.21365)
- 怎么做：ReformIR 指出"改写越多 → 召回涨、漂移也涨"，朴素合并或全量重排又贵又会退化，解法是把改写当特征、在固定重排预算下用 teacher 重排器在线估效用、主动抑制漂移；KSE-Web 在 300 条人工复核 query 上发现 LLM 扩展**没有**超过不扩展，直接扩展会引入 topic drift、泛化词与噪声改写，而"简单过滤"又会误删有用语义线索。
- 用在我们：**候选召回**（multi-query 合并）+ **排序**（漂移导致排序错位）
- 成本：诊断便宜（对比 expanded / non-expanded 的候选重叠率与 nDCG）｜局限：两篇都不是中文工程车域，"漂移"形态（型号缩写、别称、上下游工况词）**未验证**；量化漂移还需先定义 query intent。

可直接当检查项的 5 种失败模式：
1. 泛化词污染：扩出"工程车/吊车/机械"等上位词 → 召回暴涨、精度暴跌（generic terms）
2. 意图替换："25 吨汽车吊"扩成"履带吊" → 车型错了但分数很高
3. 数量绑架：改写条数多的一侧主导合并结果（drift 随改写数恶化）
4. 假阳性自我强化：PRF/LLM 用自己召回的错误文档继续扩展
5. 文本对但图错：候选对了，图是别家/示意图/水印图（对应 silent failure 的 wrong-evidence-right-answer）

### 8. 多模态链路的"静默失败"诊断（专治抓图命中率）
- 来源：[Silent Failures in Multimodal Agentic Search (SIGIR'26 SynthIR)](https://arxiv.org/abs/2607.19793)
- 怎么做：别只看"最后有没有给出一张图"，而按 6 类失败做轨迹级标注：模态捷径、幻觉 grounding、证据错但答案对、过度检索洗白、跨模态矛盾、来源幻觉；再用 cross-judge（多模型互判）+ 空白图压力测试 + 工具消融验证判断本身是否可靠。
- 用在我们：**抓图命中率**——现在的人工抽样只看"有没有图"，看不到"这张图是不是靠错的证据拿到的"。
- 成本：中（每条轨迹多次模型调用 + 抽样人工）｜局限：taxonomy 为多模态问答设计，需翻译成图片可用性维度（可对接仓库 `docs/image-usability-definition.md`）；cross-judge 一致性本身也要报告。

## 哪些只能离线，哪些必须有人

| 方法 | 候选召回 | 排序 | 抓图命中率 | 运行方式 | 必须人工的部分 |
|---|---|---|---|---|---|
| Pooling + 稳健指标 | ✅ 主用 | ✅ | – | 离线 | 判 pool（LLM 先判、人只复核分歧） |
| BEIR 式固定集 | ✅ | ✅ 主用 | – | 离线 | 一次性建集 |
| LLM 评审员 | ✅ | ✅ | ✅ | 离线批跑 | 一次性校准 100–200 对 |
| 合成 query | ✅ 主用 | – | – | 离线 | 抽检 5% |
| 弱监督 | ✅ | 辅助 | ✅ 预筛 | 离线 | 写规则（人） |
| QPP | 辅助 | 辅助 | 辅助 | 离线/线上 | 小样本相关性验证 |
| 漂移诊断 | ✅ | ✅ | – | 离线 | 定义 query intent |
| 静默失败诊断 | – | – | ✅ 主用 | 离线 | 抽样复核 + 一致性检查 |

- **纯离线可全自动**：QPP 哨兵、固定集回放、合成 query 生成、LLM 批判、静默失败的 cross-judge。
- **一次性人工（必须做，之后长期复用）**：相关性/可用性的**定义**、100–200 对校准集、pool 分歧复核。
- **持续人工（尽量少但不可省）**：每季度抽查 20–30 条新 query——这是唯一能发现"评估集自己过期"的手段。

## 给我们设计一个最小可执行评估协议

1. **冻结 200 query 快照集**：从近 3 个月日志按 车型 × 品牌 × 工况 分层抽样（固定种子），落盘 query + 当时 top-50 候选 + 抓图结果，只增不改（新 query 进 dev，不进 frozen）。这份集子是"变好/变坏"的唯一裁判。
2. **pooling 造 qrels，人工只花在分歧上**：每 query 合并 当前版 / 上一版 / 一个弱基线 的 top-20 去重成 pool；LLM 先打 0–3（候选相关性）与 0–2（图片可用性），人工只复核低置信与跨模型不一致的样本（≤5 条/query）。judged 覆盖率写进报告。
3. **四个数，各带置信区间**：Recall@50（未判按 0，同时报 nDCG′）、nDCG@10 / MRR@10、抓图命中率（可用图比例 + 首张可用图位置）、错图率（文本对但图不可用）。同一 query 集做配对 bootstrap 求 95% CI。
4. **判定规则先写死**：Δ 的 95% CI 跨 0 → "无结论"；CI 全正且 nDCG@10 ≥ +2 点 → "变好"；任一主指标 CI 全负 → "变坏"。禁止用单次点估计下结论，禁止换评估集去"救"结果。
5. **加两个便宜哨兵防自欺**：每次改动记录 (a) QPP 代理分布（分数间隔、结果重叠率）相对基线的位移，(b) 改写路 vs 非改写路的候选重叠率；骤降或整体左移 → 先人工抽查 20 条，再决定是否重跑完整评估。每季度用合成 query 给 frozen 集做一次"过期体检"。
