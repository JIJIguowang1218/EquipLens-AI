| 要素 | 现状 |

| 后台可视化 | ✅ **有真实数据**：候选清单与关联理由、门卫打分、分析 JSON（part/bbox/term/family/form/cmf）、调色板 hex |

| 音乐/音效 | ⚠️ 需要一条免费商用曲 + 少量音效 |

三个关键判断：

1. **"后台可视化"用代码做，不是比喻。** 关联推荐 = 真实的检索结果节点图；门卫筛选 = 真实的 CLIP 分数（我们存了 margin）；结构化分析 = 真实的 bbox 与四槽字段。观众看到的每个数字都来自 `data/web-runs/`。
2. **UI 只做"少量操作演示"**，用现成录屏切片 + 高清截图，不实时跑。
3. **不配旁白**（除非你要）：用大字标题 + 音乐 + 音效承载，符合"简洁清晰"的要求。

## 2. 三条故事线（三种不同的片子，不是同一片子的三个标题）

### A｜《凌晨一点四十七》— 生活前后对比
- **世界**：夜里的一张办公桌（暖光）→ 同一张桌上的产品（冷光）
- **装置**：一个人真实的一天；**形式**：分屏在痛点处铺满，随后塌缩成一块屏幕
- **观众看到**：37 个标签页、截图文件夹、空白的 PPT 模板；然后同一个位置，输入一个类目，十分钟后拿到成品
- **前两秒**：一只手关掉第 37 个标签页，屏幕角落时钟 01:47
- **节拍**：夜桌 → 标签页与截图堆积（旧方式失败）→ 产品名出现 → 三步操作 → 报告页逐块拼合 → 一句主张 → 落版
- **视觉**：暖台灯 vs 冷屏幕；报告纸色（#FAF9F6）是贯穿的"成品感"
- **声音**：房间底噪 + 键盘 + 秒针；揭晓后转干净脉冲

### B｜《一张照片的旅程》— 一个对象穿越多个世界（**推荐**）
- **世界**：搜索相册的图片墙 → 门卫的暗房 → 词表与结构层 → 报告纸面
- **装置**：一张真实施工卡车照片；**形式**：连续推进/无尽变焦——照片里的细节变成下一层世界
- **观众看到**：照片落下，放大镜环亮起（就是我们的 Logo），镜头进入环内 → 上万张候选图涌入、大部分被压暗 → 分数条把不合格的推出画面 → 框线在车上画出部件 → 四个字段逐条写入 → 照片变成一整页报告 → 十页叠成 PPT
- **前两秒**：一张卡车照片"啪"地落在灯箱上，放大镜环从画面外画进来，扣住格栅
- **节拍**：照片落下 → 候选图洪水（旧方式的失败：太多图、不知道选哪张）→ 环亮（揭晓产品）→ 三次判定（门卫/类别/型号一致性）→ bbox 与四槽（结构化）→ 成页 → 十页成册 → 一句主张 → 落版
- **视觉**：报告的纸白与墨黑；唯一强调色取自卡车本身（橙）；技术标注线
- **声音**：快门 + 纸张 + 每次判定一个"咔"；推进段低频上升

### C｜《后台车间》— 把产品当一台机器（大胆选项）
- **世界**：一条暗色产线，图片在传送带上流动
- **装置**：机器本身；**形式**：单一世界的飞行镜头，每个工位是一个概念
- **观众看到**：图片上线 → 红灯扫描（门卫）→ 分拣臂把不合格的拨走 → 打标机盖上 bbox → 压印出四槽字段 → 末端叠成一本报告
- **前两秒**：空传送带启动，红灯扫过，第一张图进入光带
- **节拍**：启动 → 废图被拨走（张力）→ 产线即产品（揭晓）→ 关联推荐以"分流轨道"可视化 → 结构化以"压印"可视化 → 成品堆叠 → 主张 → 落版
- **视觉**：工业暗调 + 金属反光 + 技术网格；与 A/B 完全不同
- **声音**：机械节律、压印、传送带低鸣

> 三者都满足"少量 UI 演示 + 后台可视化"，差别在**叙事装置**：A 靠人，B 靠物，C 靠机器。

## 3. 推荐：B《一张照片的旅程》

理由一句话：**它把"后台在干什么"变成了画面本身**（镜头穿进照片，就是穿进算法），同时不依赖真人出镜，素材风险最低，也最像我们自己产品的语言。

A 的真人素材要外购且容易拍成通用"AI 广告"；C 视觉最有记忆点，但 90 秒内讲清"关联推荐"要靠字幕，风险高。
