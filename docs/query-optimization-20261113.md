# 查询优化第一轮：相关性误杀修复 + 宽抽取（2026-11-13）

> 两个实验各只改一个变量，数据都在 `data-test/runs/`；未改生产默认（`--extract-mode` 默认仍是 `model`）。

## 1. 共性问题：0 命中不是搜不到，是护栏把“描述性车名”当成了品牌

- `_brand_group` 旧逻辑：别名表没命中时，把“第一个非数字词”当品牌；
- 长描述车名（`油田专用全驱牵引车`、`6×6 越野牵引头`、`沙漠越野重型牵引车`）被当成品牌，
  于是 `_relevant` 要求标题里出现这串描述 → 所有命中判死 → 该目标 0 图；
- 历史 1112 个 target 中 **108 次 no_hits（9.7%）**，其中 **85 次是 generic 车名**、23 次 code；
  108 条查询**全部**含 `6x6`（`normalize_query` 无条件拼的）；
- no_hits 分布跨 case（c1 24、c2 7、c4 7…），不是单案例问题。

## 2. 修复（两个都是共性 bug，不是为 c1 定制）

| 改动 | 内容 |
|---|---|
| `imagesearch._brand_group` | 只认品牌别名表；长描述里内嵌品牌用子串识别；兜底词必须是“短、无描述性词干” |
| `web.normalize_query` | 只有车型名本身带 6x6/8x8/4x4 才保留；不再给叉车/压路机硬拼 `6x6` |
| 测试 | `imagesearch 15/15`、`retrieval_engine 42/42`（新增 2 条断言） |

## 6. 结论与纪律

1. **P0 修复值得保留**：它修的是“护栏误判”，不动门卫/核验；但新增图只能以 degraded 进入交付，
   等于“数量优先”。建议给 fallback 来源打标（`query_tier`/`source_tier`），并明确它们不参与 confirmed 计数。
2. **wide 抽取不能直接默认**：候选涨 32%、备选变满，但 c2 备选出现 3 台牵引车 ——
   离类污染会削弱泛化。需要先加“类目护栏”（候选必须命中 brief 类目词或品牌+系列），再评估。
3. 不要因为 c1 单个 case 调参；本轮两个改动都在通用层（品牌识别、查询构造、抽取召回）。
4. 下一轮：wide + 类目护栏 A/B；fallback 来源标记；c3/c4/c5 回归确认无退化。
