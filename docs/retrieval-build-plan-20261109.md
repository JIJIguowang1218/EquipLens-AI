## 0. 先分清两类工作

| 类型 | 特征 | 例子 | 怎么验收 |
|---|---|---|---|
| **A. 直接实现（骨架/管道）** | 契约、状态、账本、接口、缓存、失败分类 | 任务单 schema、状态机、检查点、事件日志、适配器接口、假通道、预算/停止、证据表 | 单元测试、回放、幂等测试；不需要“选型实验” |
| **B. 需要测试取舍（策略/模型/参数）** | 有多种做法，必须用数据选 | 部件级视觉模型、重排模型、多视角查询、源优先级、并发数、停止阈值、跨类上限 | 离线实验 + 小样本人工评审；有明确指标和决策规则 |
| **C. 需要数据/标注** | 没有标注就无法判断 | 100 张部件身份/可见性标注、20–30 个任务单金标、5+20 端到端案例 | 标注协议 + 一致性检查 |

**一句话**：A 类现在就能做；B 类先做实验再定；C 类先攒数据，不要用“感觉”代替标注。

## 2. 每个阶段做什么

### P0 契约（2–3 天，直接实现）

**目标**：把“任务单 → 策略 → 状态 → 证据”的接口定死。

- 任务单 v0.3：在现有 5 例/20 例基础上加
  - `research_units[]`（B1）
  - `region_requirements` / `location`（已做）
  - `base_platform` / `configuration`（已做）
  - `strategy_ref` + `strategy_params`
  - `budget` / `stop_rules` / `negative`
- 策略库骨架：P1–P9（层级、通道、来源、查询意图、验收、停止、跨类、禁区、核验），先写接口和默认参数，不写具体模型。
- 状态/事件 schema：照 [状态机](retrieval-state-machine.md) 的 `state.json` / `events.jsonl`。
- 适配器接口：`LibraryAdapter`、`SearchAdapter`、`ImageAdapter`、`Verifier`、`Fetcher`；先写 fake 实现。
- 证据表结构：`image_evidence`、`asset_part_feasibility`。
- 失败分类：`blocked/empty/wrong_identity/wrong_config/part_not_visible/low_resolution/duplicate/budget_exhausted/no_candidate`。

**验收**：schema 单测；fake 适配器能返回固定结果；不改业务逻辑就能换适配器。

### P1 状态机（3–5 天，直接实现）

**目标**：loop 能跑、能停、能续、能回放。

- 实现 `BRIEF_READY → LIBRARY_SEARCH → GAP_CHECK → EXTERNAL_DISCOVER → FETCH → VERIFY → FILL → DEGRADE/DONE → WRITEBACK`；
- 检查点：每次转移后原子写 `state.json`；
- 幂等键：`(run_id, unit_id, target_id, candidate_id, step)`；
- 事件日志：`events.jsonl`；
- 预算/停止：单元级 `max_queries/max_rounds`，收益率停止；
- CLI：`retrieval-run --brief ... --fixtures ...`。

**验收**：
- 同一 fixture 回放，覆盖/决策一致；
- 任意状态中断，重启不重复抓取；
- 库内全满足 → 不触发外检；
- 通道 blocked → 降级/缺口报告，不误判“没找到”。

### P2 库内优先（3–5 天，A + 少量 C）

**目标**：先查库，不足才外检。

- `image_evidence` 表：资产/车型/部件/位置/视角/身份等级/分数/来源；
- `asset_part_feasibility` 表：资产 × 部件 → visible/not_visible/unknown + 方法 + 置信；
- 库内检索：按部件/位置/视角/分辨率筛候选；
- 人工录 50 条（现有 70 张过门卫图 + 分析结果）；
- 元数据 heuristic：视角 + 分辨率 + 整车构图 → candidate；不做视觉模型。

**验收**：给定“踏步 5 台”能返回库内候选；库内满足时不外检；缺口报告清楚。

### P3 外检管道（3–5 天，A；选源是 B）

**目标**：外检能跑、失败可分账、不会单点拖垮。

- 适配器：360、百度、Bing、SearXNG、Tavily（先接口 + 假数据，后真实）；
- 源健康：成功/失败/被拦计数；熔断；24h 查询缓存；
- 失败分类：blocked/empty/ok 分开记；
- 查询阶梯：型号+类目 → 型号 → 品牌+构型 → 英文名；
- 抓取/去重/门卫：复用现有 `imagesearch.py` / `gate.py`，不重写。

**验收**：录制 fixture 下 blocked/empty/ok 三种场景都能正确转移；缓存命中；熔断后不再打。

### P4 核验（1–2 周，B + C）

**目标**：判“是不是这台车、这个部件在不在、是不是原厂”。

> **2026-11-12 收窄**：只做**身份核验**；② 可见性归档（挪到人机交互，K1）、③ 原厂毙（K2）。
> 下文保留原始规划，执行以本节收窄后的口径为准。

- 身份：标题/URL/来源规则 + `region_match`/部件级视觉（实验选型）；
- ~~可见性：视角 + 分辨率 + 可裁 + 分析 `visible` 回填~~（归档 K1）；
- ~~原厂：`oem/modified/unknown` + 降权~~（毙 K2）；
- 输出：`evidence_candidate` + 缺陷标签 + 置信。

**实验 E1/E2**（见 §3）。**验收**：100 张标注上，身份 precision/recall 达到门槛。

### P5 查询与重排（1 周，B）

**目标**：同样的召回预算，候选更相关。

- 多视角锚点（B2）：`mechanism` → 2–3 个视角问题 → 查询；
- 查询阶梯（E2）：4 段；
- 重排（B5）：规则 vs cross-encoder vs 多模态；
- 源路由（B6）：按类目/域名/历史产出排序。

**实验 E3/E4/E5**。**验收**：槽填充率/相关性提升，成本可接受。

### P6 端到端（1 周，B + C）

**目标**：5 深度 + 20 广度案例跑通，人工评审。

- 输入：5 个真实输入 + 20 类目；
- 输出：命中单 + 覆盖 + 缺口 + 决策；
- 指标：槽填充率、部件可裁率、身份确认率、人工“可用率”、时间/成本；
- 对比：有/无 P4/P5 的差异。

**验收**：槽填充 ≥80%；身份确认 ≥70%；人工“不用改就能用”≥70%；编造型号 = 0。

### P7 界面/后端（之后）

- 只接真实 run；UI 暂停中，不先做；
- SSE 推事件；S1 改为“看结果 + 调整”，不是“确认清单”。

## 3. 需要测试取舍的实验（B 类）

| 实验 | 问题 | 样本 | 指标 | 决策 |
|---|---|---|---|---|
| **E1 部件级视觉** | CLIP vs SigLIP2 vs DINOv3（patch token）谁更能判“同部件/同车型” | 100 张标注（身份+可见性） | top-1 身份、可见性准确率、延迟 | 选模型/是否训练轻量头 |
| **E2 可见性/可裁** | 规则（视角+分辨率）vs 轻量模型 vs VLM | 100 张 | 可裁判断准确率、成本 | 选“粗判 + 抽样复核”组合 |
| **E3 多视角查询** | 通用词 vs mechanism 词 vs 多视角问题 | 10 个任务单 | 候选相关性、槽填充 | 选查询锚点策略 |
| **E4 重排** | 规则 vs cross-encoder vs 多模态 | 100 对候选 | precision@5、成本 | 选重排层 |
| **E5 源路由** | 360/百度/Bing/SearXNG/Tavily | 20 条查询 | blocked 率、相关率、成本 | 选主/备源 |
| **E6 并发/停止** | 并发 3/5/8；K=2/3/5 | 20 个任务 | 时间、错误、槽填充 | 选默认参数 |

**实验纪律**：
- 先冻结样本，再调参；不能调完再测同一批；
- 每个实验只改一个变量；
- 记录模型/版本/时间/成本；
- 失败也要记录，不能只留成功案例。

## 4. 建议先做的三步

1. **P0 + P1**：任务单 v0.3 + 状态机 + 假适配器 + 一个案例（沙漠牵引车）。  
   产出：能跑、能停、能续的 loop；不联网。
2. **P2**：库内证据 + 50 条人工录入 + 库内优先。  
   产出：一个真实案例的“库内命中/缺口”报告。
3. **P4 的 E1**：100 张标注 + 部件级视觉对比。  
   产出：选型结论；决定身份/可见性是否可自动化。

这三步做完，再决定 P5/P6 的投入；不要先做 UI 或大规模外检。

## 5. 不做什么（现在）

- 不先上 LangGraph/Burr/Temporal：P1 的薄状态机先跑通，框架后置；
- 不先做 UI/SSE：UI 暂停，等真实命中单；
- 不先扩 20 个新部件词表：先让 5 个真实案例跑通；
- 不先买付费 API：E5 先做小样本对照；
- 不先上向量库：P2 用 SQLite 足够。
