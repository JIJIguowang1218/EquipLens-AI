# negative A/B 与全链路参数审计（2026-11-13）

> 目的：回答两个问题——(1) `negative_terms()` + `-"短词"` 到底是什么、护栏有什么收益；
> (2) 在跑 A/B 之前，把交付链路里每个参数/开关的“讨论过没有、验证过没有”摊开，
> 特别是像 negative 这种早期设计、从未做行为级验证的内容。
>
> 本文件是审计与实验记录；结论以 `data-test/runs/ab-negative-20261113/AB-SUMMARY.md`
> 的实测数为准。

## 1. negative 机制（现状）

brief 里有一个 `negative` 列表（LLM 产出 + 代码默认）：

```
DEFAULT_NEGATIVE = ("客车", "SUV", "房车", "多车拼图", "内饰", "广告")   # briefing.py
```

`planning.negative_terms()` 只保留“能安全放进搜索 query 的短排除词”：

- 最多取 8 条输入、最多输出 **4** 条；
- 单条 **≤8 字**；
- 含指令/动词/元词（不、禁止、必须、作为、理由、模型、品牌、车型…）直接丢；
- 含标点/整句直接丢；
- 去重。

`build_query_plan()` 把结果拼成 ` -"客车" -"SUV"` 追加到**每条**查询尾部
（base/model/environment/english/unit）。它只在 plan 阶段被消费：

- 不影响门卫、核验、占槽、备选、交付判定；
- 不影响 loop 里的图片搜索——engine 的图片查询来自 `target.model`
  （`WebWorld.normalize_query`），不是 plan 里的 query 文本。

### 为什么加护栏

2026-11-12 复现：LLM 把一句 23 字的指令
「不引入具体品牌/型号或“同系列”作为设计理由。」写进 negative，旧过滤器放过，
拼进每条 query 后沙漠牵引车候选从 22 掉到 11。护栏是为了防这类“query 被整句污染”，
不是因为有证据证明排除词本身有收益。

### 已知的“收益”证据缺口

- 唯一有数据的现象是**污染时有害**（22→11），不是“干净的短词有益”；
- 没有任何 with/without 对照；
- 2026-11-13 直接探针（DeepSeek Search，20 条/query）：
  - `电动叉车 四轮 车型 品牌`：加/不加负词，20/20 URL 完全相同；
  - `大马力轮式拖拉机 4×4 车型 品牌`：20/20 相同；
  - `单钢轮振动压路机 道路施工工况 车型`：20/20 相同；
  - `沙漠/油田工况 沙漠牵引车 6×6 牵引车`：19/20 相同（1 条换位）；
  - 同一 query 连续两次：20/20 相同（搜索本身是稳定的）。
- 30 条查询的完整回放（见 §5.3）：20/30 完全相同，平均只有 **1.6/20** 条 URL 变化，
  但个别 query（c3 的 env）会换掉 10/20。结论：负词有轻微、方向不稳定的影响。

## 2. 本次 A/B 设计

- **brief 冻结**：复用 `delivery-20261112-clean` 的 5 份 API 生成 brief，不重跑、不改字段；
- **唯一变量**：`plan_candidates.py --no-negative`（`build_query_plan(use_negative=False)`），
  查询文本除 `-"…"` 后缀外逐字相同，先写 `QUERY-DIFF.json` 校验；
- **同 case 内先 with 后 without**，back-to-back，降低搜索时间漂移；
- 后续链路完全相同：`rank_plan`（同一模型/温度）→ loop（`--web-only`，固定 ranked plan）
  → audit → manifest；
- 指标：候选数、池下限、有图数、交付数、备选数、degraded、下载成功、成本（峰/谷）、耗时；
- 预注册判定（写在脚本 `render()` 里，避免事后挑指标）：
  - `without` 不得让候选池跌破 `pool.required`；
  - 交付数为主、备选数为辅；成本差 > ¥0.15/5 case 才计入；
  - without 交付不降且成本不升 → 删除 negative；交付下降/池跌破 → 保留；
  - 持平 → 保留（默认不改生产），记录“收益未证实”。

## 4. 审计中发现的问题（按优先级）

1. **negative 的收益从未被证明，且搜索层几乎无感**（本次 A/B 的核心）。
2. **`normalize_query` 无条件追加 `6x6`**：叉车 `FE4P25N`、压路机等 target 的 query
   变成 `FE4P25N 6x6`；通常第一档搜索 0 结果后再回落 `model`，白跑一次搜索，
   还可能引入跨类目结果。属早期 6×6 重卡专用逻辑外溢。
3. **rank 阶段 LLM 用量不记账**：`DELIVERY.json` 的峰/谷成本不含 rank；
   当前约 2 次/case，量级小，但口径不完整。
4. **死配置**：`page_budget.total/part_pages`、`budget.max_rounds/max_models`、
   `stop_rules`、`strategy_ref` 均不消费；schema 保留可以，但不应再被当作“已生效”。
5. **`DEFAULT_NEGATIVE` 取前 4 条**：`内饰/广告` 因截断被丢，顺序影响结果，无依据。
6. **citation_check 默认开**：成本/质量权衡未验证；它还能让 `citation_ok` 的候选
   在无 accepted 图时兜底占槽，实际影响交付构成。
7. **plan 抽取的跨调用波动**：同一 brief、几乎相同的查询，两臂候选 model 集合
   Jaccard 只有 ~0.34（c4），说明 plan 阶段噪声大于 negative 本身；
   A/B 的候选数差异不能全记在 negative 头上。

### 5.2 同一配置的重复噪声（关键）

clean baseline 与本次 `with` 臂是**同一份 brief、同一套代码、同样带负词**，
只是重跑了一次：

| case | baseline | 本次 with | Δ |
|---|---|---|---|
| c1 | 9/10 + b2 | 10/10 + b4 | +1 / +2 |
| c2 | 10/10 + b2 | 8/10 + b2 | **−2 / 0** |
| c3 | 10/10 + b4 | 10/10 + b4 | 0 |
| c4 | 6/6 + b4 | 6/6 + b4 | 0 |
| c5 | 14/14 + b4 | 14/14 + b4 | 0 |
| 合计 | 49/50 + 16/20，¥2.064 | 48/50 + 18/20，¥1.823 | −1 / +2，−12% |

**结论：相同配置的跑动本身就有 ±2 台交付、±2 台备选、±12% 成本的波动。**
A/B 两臂的交付差（0 台）小于这个噪声带；成本差 +15% 也落在噪声带内。

### 5.3 搜索层回放（机制层）

把 30 条计划查询逐条“带后缀/去后缀”各搜一次（同一时段、紧邻执行）：

- 30 条中 **20 条结果完全相同**；
- 平均 Jaccard **0.935**，平均只有 **1.6/20** 条 URL 变化；
- 变化最大的是 c3 的 `q-env`（10/20 不同），其余多为 0–2 条；
- 变化方向不稳定：c2/c4/c5 的 without 反而有更多有图候选。

### 5.4 判定

按预先写死的规则：

- 准入：c1/c2 的 without 均低于 `pool.required`（17/16 < 23）；但 with 臂的 c2 也只有 16，
  池不足是这两个类目的共性问题，不能单独归因于 negative；
- 交付：两臂 **48/50 + 18/20，完全持平**；
- 成本：without +¥0.273（+15%），但主要是多下载了图（c5 486 vs 378 张过门卫），
  不是查询本身变贵；且该差值在 §5.2 的同配置噪声内；
- 因此按规则 **保留 negative（默认不变）**，记录为“**收益未证实**”。

需要强调：**保留 ≠ 有收益**。机制层证据（20/30 完全相同、平均 1.6/20 变化）
说明它更接近一个“空操作 + 防污染护栏”，而不是一个有效的去噪手段。

### 5.5 下一步建议

1. 本轮不动生产；把 negative 标注为“未证实收益、保留仅因无回归”。
2. 若下一轮要清理，先做 **2 次重复/臂** 或固定搜索快照，再决定删除；
   以当前噪声带，单次 A/B 无法分辨 ±1 台的真实效应。
3. 真正值得先修的是审计中发现的 **`normalize_query` 无条件追加 6x6**：
   叉车/压路机的图片查询被拼上 `6x6`，通常白跑一档搜索并可能引入跨类目结果；
   这个改动会影响图片召回，不能和 negative 混在一个实验里。
4. `rank` 阶段 LLM 用量未记账，补上后再谈“全链路成本”。
