## 1. 输入流与检索计划（D12）

**原则：检索由报告规划驱动，Agent 没有自由意志，只有配置生成的计划。**

| 用户输入 | 转换 |
|---|---|
| 检索类型 | 全量建档 / 补缺检索 / 部件专项（三选一，决定任务树形态） |
| 部件选择 | vocab 表 active 项勾选子集 → 部件级检索子任务（词表即清单，PRD 附录 B v0 已预填 13 项） |
| 页面类型（暂定） | 素材需求模板：每类页面挂一张"素材需求清单"（单车页=主视角+正侧+前脸部件组……） |
| 页数选择 | 每车素材配额 = 页数 × 需求模板（A3 洪水兜底的上限来源） |

与 FR-4 素材充分性评估同构：报告规划输出需求，检索按需求补料。闭集名录锁定后只对名录内车型检索（G2 越界防线）。

## 2. 暂存机制（D14）

**暂存 = 同一数据契约下的待确认态，不是另一套格式。** 检索结果直接走 ingest 流水线入库：未对号、未打标、机器标记——"未生效"由状态字段表达（D8 两库逻辑分离）。新增唯一小设计：**检索批次号 batch_id** 写入来源记录（platform 或专用字段），支持整批审核与整批回滚。

## 3. 审核包机制（D13）

解决"检索结束后逐份点开资料"的人工痛点：

```
检索完成 → 自动生成 review.html（自包含，浏览器打开）
  ├─ 按车型分组渐进披露：摘要行（图数/完备度/待确认数）→ 图墙
  ├─ 每图：缩略图 + 尺寸/来源/URL(可点击)/置信度/质量标记/图文证据链提示
  ├─ 操作：单张与批量 接受/驳回，驳回理由必留档（偏好数据）
  └─ 导出 decisions.json
→ python -m equiplens apply-review decisions.json（一次性落账：接受→confirm 链；驳回→rejected）
```

无服务器、单机本地；此审核页即未来确认页 UI 的原型（渐进披露列表层→详情层在此预演）。每次人审产出的人机判定差异自动累积为检索评测集样本。

## 4. 分步开发闸门（R0–R7，每阶段人工验收通过才开下一阶段）

| 阶段 | 能力 | 场景 | 验收闸门 | 依赖 | 成本 |
|---|---|---|---|---|---|
| **R0 脚手架** | 检索计划配置解析（输入→任务树 JSON）；夹具渠道适配器（本地 HTML 模拟厂商页）；审核包生成器 + apply-review；batch_id | — | 计划换算正确；审核包可开可回读落账 | M3.1 补丁（hero/undo 漏洞） | 零 |
| **R1 图文检索核心** | 给定名录（测试期人工给定）+ 夹具渠道 → 抓图 + 同页文本证据 → 候选（证据链①②④齐全）→ 审核包 | S1 简化（1 品牌 1 车型）→ S1 全量 | **每张候选都能回答"为什么认为它是这台车的"**；图文对应人工评审通过；审核通过率记录为评测基线 v0 | R0 | 零 |
| **R2 名录与参数** | 名录检索任务 + 参数抽取（Facts，schema 硬约束）+ B1 歧义人审剔除 | S1 全量含名录 | 抽取 schema 通过率；参数冲突标记正确 | R1 | 零 |
| **R3 补缺检索** | 完备度缺口 → 检索任务 → 补后等级提升 | S3 | 缺口→计划换算正确 | R1 | 零 |
| **R4 替换检索** | "换更好的图"：低质素材（水印/低清）→ 同型号替代 → 审核替换（含 hero/引用一致性处理） | S3 扩展 | 替换后主图与引用不悬空 | R1 + **M3.1（hero 指针修复）** | 零 |
| **R5 部件专项 + 配额** | 部件子任务 + 页面类型/页数配额换算 | S2 + S5 | 部件命中与配额截断正确 | R1 | 零 |
| **R6 极端与兜底** | A1/A3/B1/C1 最差情况全套 | S4 | 兜底行为自动断言全过 | R1–R5 | 零 |
| **R7 真实渠道验收** | 部署 SearXNG + Crawl4AI，1 个真实小查询走全流程 | 真实 | 真实渠道产出经审核包人工验收 | **合规 B 案拍板 + SearXNG 部署形态确认** | 部署人力 |

R1–R6 全部离线（夹具渠道）零成本；R7 单列，等两项搁置决策到位。

## 5. 模拟场景定义（S1–S5，夹具离线可跑）

| 场景 | 输入配置 | 夹具内容 | 验证点 |
|---|---|---|---|
| S1 标准建档 | 全量建档：装载机 2 品牌 × 2 车型，全部件 | 每车型 1 官网页（主图+部件图+参数表） | 名录→参数→图片全链；审核包；apply-review；证据链完整 |
| S2 部件专项 | 仅"登车踏步"，跨 3 车型 | 局部特写 + 同页多车型 | 部件子任务；B3 弱关联降级；人工确认 |
| S3 补缺检索 | 用 IEVCO 库跑完备度 → 缺口任务 | 补上恰好达成 L2 的图 | 缺口→计划正确性；配额约束 |
| S4 极端与最差 | 四组最差情况 | 名录为空 / 渠道全败 / 结果洪水 / 同名不同车 | A1/A3/B1/C1 兜底自动断言 |
| S5 页面配额 | 单车页×2 + 部件页×1 | 正常与不足两种 | 需求模板→配额→计划换算 |
