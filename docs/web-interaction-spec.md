# EquipLens 网页端 · 交互说明（v1.0）

- 日期：2026-10-31
- 状态：对外评审版
- 关联：`docs/web-modules.md`（功能模块）、`docs/PRD.md`、`data-test/report-book/index.html`（版式成品）

## 1. 一句话定位

**设计师给出"看什么设备、看哪些部件"，在标准素材与 10 台车规模下，约十分钟拿回一份可编辑的竞品分析 PPT。**

## 2. 谁在用、什么时候用

| 角色 | 场景 | 诉求 |
|---|---|---|
| 工业设计师 / 设计总监 | 立项前做竞品对标 | 快、能改、来源可信 |
| 售前 / 方案策划 | 给甲方出调研报告 | 版式像人做的、能直接讲 |

## 3. 主流程（五步，可回退）

<div class="flowline">
  <div class="fl"><span>01 / S0</span><b>立项</b><em>1s</em></div>
  <div class="fl"><span>02 / S1</span><b>清单确认</b><em>10–30s</em></div>
  <div class="fl"><span>03 / S2</span><b>素材确认</b><em>30–90s</em></div>
  <div class="fl"><span>04 / S3</span><b>分析审校</b><em>20–40s / 车</em></div>
  <div class="fl"><span>05 / S4</span><b>生成导出</b><em>3s</em></div>

每一步都有"上一步"；**已确认的步骤可以回改，但不会静默丢失下游内容**（改动会提示"将影响 N 台车的分析"）。

### ① 立项（S0）

- **输入**：设备类别（必填，如"牵引车"）、目标部件（多选，默认前脸/格栅/保险杠/轮眉/踏步）、车型数量（默认 10，演示用 3）
- **输出**：`intent` 对象（结构化，不是聊天记录）
- **交互**：类别用带候选的下拉（输入即过滤）；部件用标签多选
- **失败**：类别无法识别 → 不阻断，标注 `profile_missing` 继续（通用层兜底）

### ② 清单确认（S1）

- **输入**：上一步的 intent
- **输出**：**已锁定的车型清单**（推荐 N + 方向级 + 备选 2–3）
- **展示**：表格，一行一台车；列＝车型 / 依据（品牌+型号）/ 证据等级（E3/E1）/ 关联理由 / 勾选
  - 推荐位默认勾选；方向级（provisional）标黄，需勾选才生效
  - 每行可展开看证据来源（URL、标题）
- **交互**：增（手输型号）/ 删 / 调序；"超量推荐"自动转备选
- **失败**：证据为空 → 该行标红、不可勾选（**宁可缺，不许编**）
- **退出条件**：≥1 台已勾选且有证据

### ③ 素材确认（S2）

- **输入**：清单
- **输出**：每台车 ≥1 张"整车图" + 若干部件图
- **两条来源**：用户上传（MVP 主路径，拖拽或选文件夹）／自动检索（P1.5 起，默认开、可关）
- **核心交互：三篮子**
  - `整车` / `部件` / `其他` 三列，系统自动分；用户可拖动纠错
  - 每台车必须 ≥1 张整车图，否则该车标红"缺整车图"，不进入下一步
- **识别与归组**：系统给"疑似同一台车"分组 + 车型候选；用户点选确认
- **失败**：无法归组 → 进"未归组"托盘，不丢；可手动指派

### ④ 分析审校（S3）

- **输入**：每台车的整车图 + 部件清单
- **输出**：一车一页的分析（三词 + 前脸分析 + 5 个部件四槽）
- **展示**：页面即成品（16:9），所见即所得
- **三类可改**：
  1. **裁框**：点部件图 → 在原图上调框（跨图也能拖，见裁框编辑器）
  2. **文字**：直接点文字块改（contenteditable），或重生成这一段
  3. **版式**：开"编辑布局"后拖块、缩放、吸附对齐；文本自动缩字号
- **进度**：逐台生成，右上角显示 `3/10 生成中`，可"跳过这台"
- **失败**：单台失败不阻断整批，标红可重试

### ⑤ 生成导出（S4）

- **输入**：全部已确认的页面
- **输出**：PPTX（可编辑主交付）、PDF（只读交付）、网页版翻页册
- **交互**：预览 → 下载；文件名 `EquipLens-<类别>-<日期>.pptx`
- **失败**：导出失败保留工程，可重试

## 4. 全局交互原则

1. **对话为壳、结构化对象为核**：不做自由聊天窗口；确认发生在表格/页面对象上
2. **歧义问人，明确静默推进**：置信度 <0.8 才打断
3. **永远可回退**：五步任意回改，下游标"需重算"但不自动清空
4. **进度可见**：任何 >3 秒的操作都有进度与"当前在做什么"的文案
5. **失败可解释**：错误文案说清"哪一步、为什么、怎么办"，不出现裸报错

## 5. 状态与反馈

| 状态 | 表现 |
|---|---|
| 空 | 一句指引 + 一个主按钮，不写说明书 |
| 加载 | 进度条 + 当前步骤文案（"正在检索候选车型…"） |
| 部分失败 | 该行标红 + 悬浮说明 + 重试按钮 |
| 完成 | 直接给结果，不弹祝贺弹窗 |
| 中断 | 刷新后回到上次步骤，状态不丢 |

## 6. 明确的非目标（本期不做）

- 用户账号 / 多项目 / 权限
- 自由对话式助手
- 跨车对比结论页、情绪版、品牌基因页
- 移动端适配（桌面优先，1280 起）

## 7. 已确认的交互取舍

1. **首页**：立项为主；最近项目在 MVP 后置，避免首屏变成项目管理器。
2. **自动检索素材**：P1.5 起默认开、可关；MVP 以上传为主，避免把检索依赖带进最小闭环。
3. **分析审校**：一屏一车 + 缩略图条，方便逐台跳转与批量检查。
