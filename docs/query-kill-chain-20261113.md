# 第二段“判死链”复盘：为什么车会被判死，以及去表化的修法（2026-11-13）

> 只读分析 + 契约改动（来源分级）。未跑检索实验。数据口径：`data-test/runs/**` 历史产物。

## 1. 这次到底修了什么（先对齐口径）

**不是第二段宽查询回退。** 第二段查询仍由 `normalize_query(车型名)` 生成，没有回退到第一段宽查询。
实际改的是两处“判死条件”：

| 改动 | 旧行为 | 新行为 |
|---|---|---|
| `imagesearch._brand_group` | 品牌别名表没命中时，把“第一个非数字词”当品牌 | 只认别名表；长描述里内嵌品牌用子串识别；兜底词必须“短、无描述性词干” |
| `web.normalize_query` | 无条件拼 `6x6` | 车型名本身带 6x6/8x8/4x4 才保留 |

效果：同一批 10 个历史 `no_hits` 目标，有命中从 0/10 → **9/10**；端到端 c1 8/10 → 10/10（新增 2 台为 degraded），c2 持平。

## 3. 关于“品牌表”：来源与问题（不是本轮新建的）

- 代码里的 `BRAND_GROUPS` / `_BRAND_LOOKUP` / `alias_query` 是**既有实现**，引入于
  commit `c44e0e3`（“检索：交付守卫、审核页双口径、外国品牌召回修复”），用于两件事：
  1. 相关性护栏判断“标题里的品牌对不对得上”；
  2. `alias_query` 把拉丁车型名改写成 360 更容易命中的中文查询。
- “品牌不在别名表里”= 该品牌名不在 `BRAND_GROUPS` 这几十个条目中。代码会退回
  “把第一个非数字词当品牌”（旧）或“只保留车辆词门槛”（新）。
- 你的判断是对的：**50% 的 target 没有品牌组，不代表它们是错车，只代表我们不认识这个牌子。**
  修复后它们不再被 0 图判死，但核验拿不到品牌/型号证据 → identity=unknown → 只能进 degraded。
  也就是说：**这不是“降低了它们的信度”，而是“我们本来就无法证明它们的身份”**；修复前是直接丢弃。

**结论**：品牌白名单本身就是“表查询”，正是你反对的那种设计。它应当降级为“加分项”，
不能作为判死门槛。替代表法见 §5。

## 5. 去表化的替代设计（不枚举类目/品牌）

### 5.1 用“发现来源”代替“类目词表”

wide 抽取在 c2 混进 3 台牵引车（`Giga 港口牵引车`、`龙V 集装箱运输车`、`HOWO NX 牵引车`）。
检查它们的来源：**4 台全部只被 `environment` 维度查询发现，且只有 1 个来源**，
没有一条来自 `base`/`model` 维度。所以不需要“正面吊/集装箱正面吊”词表，只需规则：

> 候选必须至少有一条来自 `base`（或 `base`+`model`）维度的来源；只有 `environment`/`topup`
> 来源的候选降权到 pool 尾部，不直接删除（保留可追溯、可捞回）。

这是**来源证据**规则，不是词表；对任何类目都成立。风险：environment 维度独有的合法候选会被降权
（可接受，降权不是删除）。

### 5.2 用“字符串证据”代替“品牌白名单”

身份判定改为三档证据（都不需要品牌表）：

1. 型号码（正则）命中标题 → confirmed；
2. 拉丁/数字 token 命中，或 2 个以上非通用中文片段命中 → probable；
3. 否则 unknown。

品牌表只作为“额外加分”，不再是门槛。这样未知品牌（美科斯、TOMAC、五岳）也能靠
“型号/系列/数字”拿到 probable，而不是永远 unknown。

### 5.3 把“展示名”和“检索键”分开

不要把“让 LLM 改名”当作解法（会伤召回）：保留 LLM 给的展示名，**确定性解析**出检索键：

- 有型号码 → `品牌? + 型号码 + 构型?`
- 无型号码 → `车系/品牌? + 类目短语(从 brief 的 class 取) + 构型?`

这样括号里的型号码（#3）、长描述（#4）同时被解决，而且不需要任何“类目/品牌”表。
