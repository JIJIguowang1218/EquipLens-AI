> 1. **`data/part_views.json` 毙掉**：不再做“部件→视角”静态表或检索前视角预判。
>    视角交给用户看图判断；模型不因视角等待/过滤。`part_requirements[].views` 只作为
>    分析提示，不作检索门槛。
> 2. **`data/part_axes.json` 不建静态表**：关系轴（exact/environment/platform/cross）
>    改为每个设计对象由 `task-brief@v2` 输出 `relation_axis`，按请求判断；
>    静态表只在未来需要确定性路由且已有人工确认数据时作为缓存，不作为种子白名单。
> 3. 设计轴（form/proportion/structure/cmf/...）与关系轴不是一回事：前者决定“看什么”，
>    后者决定“检索范围”；两者都由 LLM 按对象输出，不查表。

**v0.2 相对 v0.1 的变化（产品负责人 2026-10-31 补充）**：
1. "证据"重定义为**图片**：一页需要 1~2 张主图，部件图是主图上的**裁图**；文本可由分析模块生成，**不再是门槛**。
2. 页槽判据、停止条件、放闸触发全部从"文本覆盖"改为"主图可得 + 部件可裁"。
3. 清单**超量推荐**（推荐 N + 备选 2~3），爬完自动定稿、超出作备选。

## 1. 它解决什么

用户输入是**「车型类别（+ 具体车型）+ 要分析的部件」**，输出必须是一份**能在报告页数内排得下的检索清单**：

> 用户说"沙漠牵引车，重点看踏步、防护栏、底盘" → 本模块 → 12 个页槽的目标（精确类目 + 环境特化 + 基型参照）+ 2~3 个备选 → 每个目标带理由与配额 → 人工确认 → 交检索。

三条硬约束决定了它不是"越全越好"的推荐器：

1. **页数预算**：报告约 20 页，整车页 10~14 个页槽（§3）；
2. **真正的稀缺是"能撑起一页的图"，不是文本**：段落/文字可由分析模块补，主图不可凭空生成；
3. **不确定的判断不能写死**：轴的选择、够不够、要不要放闸，都是判断（模型/人），只有配额、账本、schema 是硬规则。

## 2. 位置与边界

```
用户输入 ──► intent ──►【L1.5 清单推荐】──► 确认包 ──► 图库/检索 ──► 主图+裁图 ──► 页槽
                            │                  │
                     部件→视角/轴表(data)   库内已有素材优先（query.py）
```

**在范围内**：目标（车型/类目/部件）扩展、层级阶梯、页槽分配、超量推荐与备选转正、排序、清单确认落账、覆盖度判定与放闸决策。

**不在范围内**：具体查询词生成（`build_plan` 已有）、抓取与 robots（L2）、段落打分与闸门（L3）、裁图与排版（下游）、分析文本生成（分析模块）。

## 3. 页面预算与"一页需要什么"

### 3.1 页数拆解（参数，不写死）

| 页类 | 页数 | 版式内容 |
|---|---:|---|
| 封面 / 封底 | 1 + 1 | — |
| 方法与来源 / 目录 | 1 | — |
| 情绪版 | 1~2 | 待定（PRD 开放项） |
| **整车页** | **10~14** | **一车一页**：1~2 张主图（展示大部形象）+ 3~4 个部件裁图 + 分析文本框，排布紧凑 |
| **部件专项页** | **0~2** | **一部件一页**：以"该部件的图 + 自己的文本框"为单位，可排 5~6 个单元（跨车型对比）；需用户确认 |
| 合计 | ≤ 20 | 校验：12 整车 + 2 专项 + 5 固定 = 19 ✓ |

`page_budget` 入参默认 `{total: 20, vehicle_slots: 12, part_page_slots: 2, fixed_pages: 5}`；
硬校验：`vehicle_slots + part_page_slots + fixed_pages ≤ total`。

### 3.2 页槽 = 检索深度上限

- **一个页槽拿到 1 张合格主图 + 1 张备用即停**——不追求多视角、不追求图量，因为部件图都是从主图裁的。
- 两个停止条件：单目标"主图够用"即停；全网"够 12 个页槽"即停。
- 凑不满时输出**缺口报告**（哪几个槽空、是"没车"还是"主图不合格"），不降标准凑数。
- 12 个槽的图量级 ≈ 12~24 张主图 + 36~48 张裁图（裁图零额外检索成本）。

### 3.3 证据与"够不够"（图片口径）

**合格主图**（硬判据，先粗后精）：

| 项 | 要求 | 判法 |
|---|---|---|
| 主体 | 单台车、主体完整、无遮挡 | 门卫（`gate.py`）现成：单台/多车/客车反例 |
| 分辨率 | 长边 ≥ R（默认 1200px） | 图片元数据，零成本 |
| 视角 | 主视角（hero_45 / side，可含 front） | `probe.py` 视角标签（已收口为嵌入式元数据） |
| 可用性 | 能支撑请求部件裁图 | ~~`part_views.json` 粗判~~（已毙 K3）；由人机交互/人审判断，VLM 后置 |

**两档判据**：

| 用途 | 判据 | 备注 |
|---|---|---|
| 整车页 | ≥1 张合格主图 + 1 张备用；请求部件中 **≥3 个可裁**（请求 ≤3 个时要求全覆盖） | 少一个部件就少一个文本框，页仍成立但降级，需标记 |
| 部件专项页 | 该部件在 **≥K 台车**的主图上可裁（K 默认 5，对应一页 5~6 单元） | 单台车裁图算 1 个单元 |

**文本不再是门槛**：文本只作加分项（定调/语汇/事实），缺文本不阻止页槽成立，也不触发放闸。这条对成本影响很大——文本检索只在"推荐集"上跑，备选不跑。

### 3.4 主图与裁图的可行性约束

- 单张主图通常只能覆盖 2~3 个部件（踏步/底盘常在低角度或侧视才可见），**要支撑 3~4 个部件，清单应要求 ≥2 个视角（前 45° + 侧）**；
- ~~部件→可接受视角映射放数据（`data/part_views.json`）~~：**已毙（K3，2026-11-11）**——视角由用户看图判断，不做检索前预判；
- 清单里记录"该目标预计能裁出哪些部件"，作为页槽合格与否的依据之一。

```json
{
  "list_version": "v0.2",
  "intent_ref": "intent.json",
  "page_budget": {"total": 20, "fixed_pages": 5, "vehicle_slots": 12, "part_page_slots": 2},
  "buffer": {"requested": 12, "extra": 3, "rule": "max(2, ceil(0.15*N))；薄类目 25%"},
  "targets": [
    {"id": "t01", "kind": "vehicle", "status": "recommended", "tier": 1,
     "relation": "exact", "category": "沙漠牵引车", "models": ["豪沃 6X6"],
     "slots": ["vehicle:1"],
     "parts": [{"part": "踏步", "views": ["side", "hero_45"]},
               {"part": "防护栏", "views": ["side", "rear"]}],
     "images": {"in_library": 2, "need_crawl": false, "hero_candidates": 3},
     "reason": "精确类目命中；库内已有 2 张合格主图（长边 1600/2400），可裁踏步+防护栏",
     "priority": 1.0},
    {"id": "t13", "kind": "vehicle", "status": "backup", "tier": 2,
     "relation": "environment", "category": "沙漠环境用车", "models": [],
     "slots": [], "borrowed": true,
     "reason": "防护栏/进气防护属环境特化件；仅备选，主图确认后转正"}
  ],
  "part_pages": [
    {"part": "踏步", "candidates": ["t01", "t05", "t07"], "vehicles_covered": 5,
     "ready": true, "borrowed_share": 0.2}
  ],
  "coverage": {"slots_filled": 12, "slots_requested": 12,
               "by_part": {"踏步": {"vehicles_croppable": 5}}},
  "decisions": [{"at": "coverage_probe", "tier": 1, "action": "open_next_tier",
                 "reasons": ["防护栏 仅 4 台车可裁 < 5"]}],
  "backlog": [{"target": "徐工 X 系列", "why": "备选（主图质量未知）"}]
}
```

字段纪律：

- **`tier` + `borrowed` + `status`**：每条目标都要能回答"凭什么进清单、是直证还是类比、是推荐还是备选"；
- **`images`**：先给"库内已有几张、要不要爬"，这是成本与放闸的直接依据；
- **`reason` 必填**：写"提供什么证据（可裁哪些部件/什么叙事）"，不写"相似"；
- **`slots`**：每个页槽唯一主目标；备选 `slots` 为空，转正时才占槽。

## 5. 关联轴与部件阶梯

四轴（数据驱动：`data/part_axes.json` + `data/category_profiles.json` 扩展）：

| 轴 | 何时用 | 沙漠牵引车例子 |
|---|---|---|
| `exact` 精确类目 | 永远第一层 | 沙漠牵引车本类 |
| `environment` 环境/工况特化 | 部件"因环境而设计" | 防护栏、进气/散热、底盘离地、踏步防滑 |
| `platform` 基型平台 | 部件"继承平台造型" | 前脸、驾驶室轮廓、家族化特征 |
| `cross_vehicle` 跨车型构型 | 功能件，构型可跨类目比较 | 踏步、爬梯、把手、后视镜 |

**阶梯按部件生成**，默认上限到 `platform`；`cross_vehicle` 需用户勾选"接受类比证据"，该层证据一律标 `borrowed`。

## 6. 放闸规则（惰性）

```
库内盘点 → tier1 精确类目 → 挑主图/判可裁 → 页槽填充
   ├ 够 → 定稿（推荐 + 备选）
   └ 不够 → 开下一层（environment → platform）→ 再跑 → 再判
              └ 到上限仍不够 → 报缺口（不降标准）
cross_vehicle：默认关闭；用户勾选后才开
```

**触发条件是图片而不是文本**：页槽填不满（没有合格主图）、或请求部件在主图上裁不出，才放下一层。文本不足不触发（分析模块补）。

四条护栏：

1. 放开层只松"对象"，不松"具体性"：仍须能裁出请求部件，不接受"随便一张车图"；
2. 放开层关闭 G 档宏观通道（文本侧），避免用空话凑数；
3. 上限写配置，模型不能自行突破；
4. 每次放闸写 `decisions`，可审计。

## 7. 页槽分配、超量推荐与备选转正

优先级：`tier` 小优先 → 同层按可填充度（库内主图数、`domainbench` 的 A/千字、历史批次产量）→ **构型族去重（同族最多 2 台）** → 至少 1 台环境特化车承担"这个工况为什么这么做"的叙事 → 其余进 `backlog`。

**超量推荐（v0.2 新增）**：

| 层 | 超量规则 | 成本控制 |
|---|---|---|
| 清单层 | `extra = max(2, ceil(0.15 × N))`；薄类目 25% | 备选也爬图（便宜） |
| 素材层 | 每台车 2~3 张主图候选 | 只裁不重爬 |
| 文本层 | **只跑推荐集**，备选不跑 | 备选转正后再补文本 |

三条执行规则（缺一就成脏数据）：

1. **转正规则**：仅当推荐集某台"主图判废/人审驳回/工作图不足"时，从备选按 `priority` 顶上，并落账；
2. **展示规则**：确认页明确"推荐 12 / 备选 3"，超出的自动标为备选，不混进推荐；
3. **占槽规则**：备选不占页槽，转正才占——否则页数校验被撑破。

**定稿的自动判据**：主图合格（主体/分辨率/视角）+ 可裁部件数达标；不达标→备选转正；全不达标→报缺口并请人决定（补采/换类目/缩页数）。

## 8. 与现有代码的接口（最小改动）

| 需要 | 现状 | 改动 |
|---|---|---|
| 库内素材盘点 | `query.py` 组合过滤（视角/车型/对号/质量） | 直接复用，按车型查"合格主图数" |
| 每个 target 跑一次检索 | `textrun.run` 单意图 | 清单模块为每个 target 生成 intent（`category/models/part_focus`），共用 run_id |

## 11. 风险

| 风险 | 处置 |
|---|---|
| 主图裁不出请求部件 → 页槽降级 | 清单阶段就记"预计可裁部件"，降级在确认页可见 |
| 单视角主图裁不全 3~4 部件 | 强制 ≥2 视角（§9 参数 1） |
| 备选混进推荐、撑破页数 | `slots` 只给推荐集；备选转正才占槽 + 落账 |
| 薄类目备选也救不回 | 缺口报告 + 请人决定（补采/换类目/缩页数），不自动降标准 |
| 图质判据过严导致大面积判废 | R 与"可裁"先用粗判（视角+分辨率），VLM 复核后置；参数可调 |
| 文本价值被高估 | 文本只作定调/语汇加分，不参与页槽成立判断 |
