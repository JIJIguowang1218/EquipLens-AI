## 0. 一句话

**暗房**：照片是唯一的高亮面，UI 退成石墨与发丝线。**激光绿**只回答“现在轮到你 / 系统正在动”；关联度改成**四个小面积分类色**，每条记录都有自己的色彩索引、文字标签和独立区域；报告页保留一张被灯照亮的纸。

这一版不是“把浅色反相”，也不是“把琥珀换成绿色”。核心变化是：**结构化的内容不再当普通段落排版，而是按功能拆成头部、字段、状态和记录单元。**

## 1. 设计审查：Unparalleled UI 指出了什么

安装位置：`~/.dsh/skills/unparalleled-ui`（来源 [Phantom-Con-Artist/unparalleled-skillset](https://github.com/Phantom-Con-Artist/unparalleled-skillset)，MIT）。它专门审“dashboard / data table / editor / 复杂工作流”的界面，并明确把以下几类当成问题：

| 审查发现 | 本版处理 |
|---|---|
| 用横线切分列表行，行与行没有独立区域 | S1 清单改为**独立记录胶囊**：每条有自己的表面、3px 层级色左缘、9.5px 层级标签；不再用 `border-bottom` 切 |
| “关联分析 / 清单 / 部件分析”是 9px 的 eyebrow，重要信息被当普通文本 | 全部改为**面板头**：15px/600 标题 + 计数 chip + 独立头部表面 + 底发丝线；`关联分析`另加 3px 激光绿模块标记 |
| 关联度只有文字标签，颜色没有承担索引 | 四个分类色（绿 / 青 / 橙 / 玫瑰）只出现在 3px 条、5px 点、9–10px 胶囊；文字和跨类虚线仍然兜底 |
| 卡片文字区只是“名称 / 副标题 / 标签”三行流 | 卡片改成**数据牌**：名称、`构型 │ 品牌` 两字段、关联度胶囊；图片与文字之间加发丝线 |
| 卡片选中只靠勾选框，不够明显 | 未选图片压到 46% + 去饱和 + 名称转灰；选中图片复原、表面抬起、激光绿实心勾；不做彩色整圈 |
| 状态点脉冲、小标签闪烁 | live 点改为**稳定**激光绿点 + 底部进度线，不再 pulse；进度由真实计数驱动 |
| 一处颜色用在所有地方 | 激光绿只给主行动 / 选中 / live / 模块标记；关联度用四个“数据索引”色，面积受限 |
| S2 的 CMF / 族 / 意图全挤成一行 | CMF / 族改为**两列字段框**（标签在上、值在下）；意图单独成行；状态改为带色点的 chip |

> 该 skill 的“一个强调色”原则与用户“条目内要有颜色区分”的要求存在冲突。这里按用户明确要求执行：**主强调色仍只有一个（激光绿），关联度是数据分类色，不是第二个强调色**；分类色只占小面积，且从不单独承载意义。

### 卡片参考（开源项目）

- **[shadcn/ui Card](https://ui.shadcn.com/docs/components/card)**：卡片不是“一个白盒子”，而是 header / content / footer 的功能分区。本版把卡片拆成图片区、数据牌、状态胶囊。
- **[Cal.com](https://github.com/calcom/cal.com) 的 event type 卡**：封面/标题/元信息/状态并置，状态用小型 chip 而不是一整行彩色。本版借用“图片 + 标题 + 规格 + 状态”的纵向节奏。
- **[Vercel Commerce](https://github.com/vercel/commerce) 的 product card**：图片是主角，名称/规格/价格保持对齐；卡片内部靠字号与间距分层，不靠彩色底。本版借用“图片优先、元信息紧凑、状态独立”的结构。

## 2. 色板

### 2.1 中性色（结构）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#0A0B0D` | 页面底；近黑不纯黑 |
| `--surface` | `#121418` | 卡片、面板 |
| `--surface-2` | `#161A1F` | 卡片悬停 |
| `--surface-3` | `#1C2027` | 浮层、toast |
| `--line` | `rgba(232,238,246,.07)` | 发丝线、卡片边 |
| `--line-2` | `rgba(232,238,246,.13)` | 可交互控件边、字段分隔 |
| `--ink` | `#ECEFF3` | 标题、当前态 |
| `--ink-2` | `#A9B1BB` | 正文、次级信息 |
| `--ink-3` | `#7C8591` | 元信息、说明 |
| `--ink-4` | `#5C646F` | 占位、极弱标签 |

### 2.2 主强调色：激光绿

| 令牌 | 值 | 用途 |
|---|---|---|
| `--accent` | `#C7F14F` | 当前阶段刻度、主按钮、选中勾、live 点、关联分析模块标记 |
| `--accent-hi` | `#D8FB66` | 主按钮悬停 |
| `--accent-ink` | `#101405` | 激光绿底上的文字（14.34:1） |

激光绿偏黄、较亮，接近工业激光/荧光标记，不是“赛博青”。它只承担“现在/你/已选”这一类语义，不做大面积底色，也不做每条记录的分类色。

### 2.3 关联度：四个小面积分类色

| 轴 | 令牌 | 值 | 索引含义 | 面积 |
|---|---|---|---|---|
| 精确类目 | `--t-exact` | `#5FD69F` | 直接可比 | 3px 左条 / 5px 点 / 9–10px 胶囊 |
| 环境特化 | `--t-env` | `#5AC6E6` | 同工况参照 | 同上 |
| 基型平台 | `--t-plat` | `#E7A15F` | 造型继承 | 同上 |
| 跨车型 | `--t-cross` | `#DE7C87` | 仅作备选 | 同上 + 虚线/灰化 |

这是用户明确要求的“绿 / 红 / 橙”类分类索引的落地：绿→精确、青→环境、橙→平台、玫瑰→跨类。它不像“单一明度阶梯”那样只靠亮度，而是让 8 条记录在扫视时能被颜色快速分组；同时每条都保留文字标签，跨类再加虚线，颜色不是唯一信号。

### 2.4 流程状态（S2 部件行）

| 状态 | 颜色 | 形态 |
|---|---|---|
| 已框定 | `--s-framed #8FB4C4` | 3px 钢蓝左条 + “已框定” chip |
| 本图可见 · 待框选 | `--s-pending` = 激光绿 | 左条 + 文字 + 微光；唯一“需要你动手”的状态 |
| 在 图 N 框选 | `--s-elsewhere #7C8A9A` | 暗条 + “在 图 2 框选” |
| 本图不可见 | `--s-hidden #39424C` | 几乎隐去的条 + “本图不可见” |

### 2.5 对比度实测

| 前景 | 背景 | 比值 |
|---|---|---|
| `--ink #ECEFF3` | `--surface #121418` | 15.99 |
| `--ink-2 #A9B1BB` | 同上 | 8.51 |
| `--ink-3 #7C8591` | 同上 | 4.94 |
| `--accent #C7F14F` | `--surface` | 14.16 |
| `--accent-ink #101405` | `--accent` | 14.34 |
| `--t-exact #5FD69F` | `--surface` | 10.19 |
| `--t-env #5AC6E6` | 同上 | 9.35 |
| `--t-plat #E7A15F` | 同上 | 8.48 |
| `--t-cross #DE7C87` | 同上 | 6.44 |
| 纸面正文 `#191A1D` | 纸 `#F7F4EC` | 15.83 |
| 纸面弱文 `#5A574F` | 纸 | 6.56 |
| 纸面元信息 `#6B665B` | 纸 | 5.20 |

分类胶囊用 12% 同色底 + 30% 边框；实测文字对比在 **5.14–8.18** 之间。9.5px 的清单 tag 也在 5.4 以上。颜色从不单独承载语义：每个胶囊、每个左条、每个图上框都有文字或线型配合。

### 2.6 用色纪律

1. 激光绿只用于“现在/你/已选”：主按钮、选中勾、live 点、当前刻度、关联分析模块标记。
2. 关联度是**数据索引**，不是强调色：每条只用 3px 左条 + 9–10px 胶囊 + 5px 点，绝不整行填色。
3. 颜色必须配文字；跨类再加虚线；选中必须同时有勾、图片明度差和表面差。
4. 不做整圈彩色描边；选中用**实心勾 + 图片复原 + 表面抬起**。
5. 报告纸是唯一的大面积浅色；不要为了“统一”把纸改成暗色。

## 3. 字体

### 3.1 选型

| 角色 | 字体 | 字重 |
|---|---|---|
| 拉丁 / 数字 / 界面 | **Equip Sans**（基于 IBM Plex Sans，variable） | 100–700 |
| 简体中文 / 中文标点 | **Equip Sans SC**（基于 IBM Plex Sans SC 子集） | 400 / 500 / 600 |
| 计数、页码、序号、字段标签 | **Equip Mono**（基于 IBM Plex Mono） | 400 / 500 / 600 |

Plex 的方切、紧凑字幅和工程感贴合设备/测量语境；Plex Sans 与 Plex Sans SC 同属一个设计家族，中英混排不会出现两套骨架。等宽只做数据和标签，不做标题。

### 3.2 商用与许可

- 三套字体均为 **SIL Open Font License 1.1**：允许商用、嵌入、子集化、随产品分发；不允许单独售卖字体本身。
- IBM Plex 带 **Reserved Font Name “Plex”**，所以子集文件已把 family / full / PostScript / named instance 全部改成 **Equip Sans / Equip Sans SC / Equip Mono**，字形轮廓未改。
- 许可原文在 `fonts/OFL-*.txt`；来源、字符数、子集方法在 `fonts/README.md`。
- 这解决了原稿“Inter 没有中文，中文实际落到 Microsoft YaHei / PingFang”的隐性问题：中文字体随包分发，跨平台一致。

### 3.3 此版的排印角色

| 角色 | 字号 / 行高 | 字重 |
|---|---|---|
| S0 标题 | `clamp(30px,3.55vw,45px)` / 1.08 | 600 |
| 面板头（关联分析 / 清单 / 部件分析 / 页面） | 15 / 1.3 | 600 |
| 分析判断句 | 12.5 / 1.72 | 600 |
| 分析正文 | 11.8 / 1.9 | 400 |
| 卡片名称 | 13.5 / 1.25 | 600 |
| 卡片规格 / 品牌 | 10 / 10.5 | 400 |
| 清单名称 | 12.5 / 1.25 | 600 |
| 字段标签（CMF / 族 / 意图） | 8–8.5 等宽 | 400 |
| 计数 / 页码 | 9–9.5 等宽 | 400–500 |

数字全部 `tabular-nums`；中文正文 1.9 倍行高给足呼吸。

## 4. 组件与卡片

### 4.1 面板头（取代 eyebrow）

```
▍ 关联分析                         [ 8 台 · 6 推荐 + 2 备选 ]
──────────────────────────────────────────────────────────
```

- 标题 15px/600，中文字体，不用 9px 等宽大写 eyebrow。
- 右侧计数是 chip：#0D1013 底 + 1px 发丝线 + 9.5px 等宽。
- 头部是独立表面（浅渐变）+ 底发丝线；`关联分析`左侧 3px 激光绿标记，`清单/部件分析/页面`只靠字号与计数 chip 建立层级。
- 分析正文先读一句**判断句**（12.5/600），再读展开段（11.8/1.9）；左侧中性 2px 规则线把它从普通段落变成“结论模块”。

### 4.2 S1 车辆卡

```
┌──────────────────────────────┐
│  [照片 contain + 模糊垫底]    │
│  1 / 4                 [✓]   │
├──────────────────────────────┤   ← 发丝线
│  德龙X3000                   │   ← 13.5/600
│  6×6  │  陕汽                │   ← mono 10 / 1px 竖线 / 10.5
│  ● 精确类目 · 直接可比        │   ← 10px 胶囊 + 4px 点
└──────────────────────────────┘
```

- **选中**：图片复原（100%）、表面 `#151A21`、激光绿实心勾、名称白；没有彩色整圈。
- **未选**：图片 46% + 灰度、表面 `#0E1115`、空勾、名称转灰；规格与胶囊只降到 80%，仍可读。
- **备选**：虚线边、图片 40% + 灰化、无勾选框。
- 图片与数据牌之间是 1px 发丝线；规格用 `6×6 │ 陕汽` 两字段（分隔点改为 1px 竖线，文字仍在 DOM 中）；关联度是独立胶囊，不再是一行裸文字。
- 8 张卡三行完整放得下（卡高 213，最后一张底 789 < 内容区 810）。

### 4.3 S1 清单：独立记录胶囊

```
┌─3px 层级色───────────────────────────────┐
│ 01   德龙X3000                 ● 精确     │
│      6×6 │ 陕汽                           │
│      6x6 沙漠越野构型，三件部件可裁……      │
└──────────────────────────────────────────┘
```

- 不再用横线切行；每条是独立表面 + 1px 边框 + 左 3px 层级色 + 9px 圆角。
- 层级标签是带 3px 点的 tinted capsule；序号中性；名称 12.5/600；原因 10.2/1.58 两行。
- 8 条记录在 514px 高的面板里滚动；每条的区域边界一眼可见。

### 4.4 S2 部件卡（规格卡）

```
▌ 01  grille  横置多层格栅                 ● 已框定
   三层横向饰条贯通车头，止于大灯内缘。
   两端收进灯腔，宽度略窄于前脸。
   ┌ CMF ─────────┬ 族 ─────────┐
   │ 钢板·哑黑喷涂 │ 钣金件      │
   └──────────────┴─────────────┘
   意图  横向拉宽车头视觉，压低头部重心。
```

- 左侧 3px 状态条 = 流程状态；状态 chip 带同色点，不只是文字。
- 形制两句是主内容；CMF/族是**两列字段框**（标签在上、值在下，中间 1px 分隔）；意图单独一行，上方发丝线。
- 选中只改表面与边线，不覆盖状态条语义。

### 4.5 S3 报告纸

- 暗色工作台 + 纸：纸 `#F7F4EC`、正文 `#191A1D`、元信息 `#6B665B`、封面细线 `#5F6E1E`。
- 页面预览头改为 15px/600 + 页码 chip；页块选中用墨色 1.5px 描边 + 纸色手柄。
- 报告纸是暗色界面的视觉锚点，不要改成暗色。

## 5. 没有动的部分

- 四页的**可见文案**与浅色版一致；S1 只增加了视觉 spans（判断句 `<strong>`、规格分隔、清单 tag 移出 `.rt`），没有增删词句。
- 功能区与按钮：rail、进度、状态条、8/4 栅格、dock 三件套、S2 控件行、S3 页预览均在原位。
- 栅格：内容区 1112，8 栏 736 / 4 栏 360，gutter 16。
- `data.js` 未改；图片仍指向 `data-test/ab-images/` 的真实实拍。
- 唯一的行为修复：S2 点“在 图 2 框选”原本不会切图（`st === 'elsewhere'` 永远不成立），改为 `startsWith`。
