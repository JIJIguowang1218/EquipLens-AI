## 0. 本次修订的五个结论

1. **01、02 各压缩为一页**：01 只回答“是什么、解决什么问题、边界在哪”；02 只回答“谁在用、在什么任务里用、现在怎么凑合”。
2. **AI 价值前置为 03**：在讲功能之前，先讲清楚产品形态、核心价值链路和护城河。功能页是价值链路的证据，不是功能清单。
3. **明确产品类型**：不是通用 Agent，也不是纯 Workflow，而是 **Agent-augmented workflow（混合编排）**：workflow 负责骨架与交付，agent 负责关节判断，确定性护栏负责合规与可回退。
4. **护城河要单独成页**：模型不是护城河；领域 schema、证据基础设施、修正数据、模板资产与评测集才是。要与通用 Agent / 通用 AI PPT / 图库+人工三种替代方案做结构化对比。
5. **语言去情绪化**：删除设问式、对话式、口号式标题；改用“定义—判断—证据—边界”的产品经理语言。每一页标题就是一个结论。

## 2. v2 叙事逻辑

```text
问题域（01）
  → 用户与任务（02）
  → 产品形态与价值（03）
  → 能力链路（04）
  → 技术实现（05）
  → 场景验证（06）
  → 落地路径（07）
  → 术语与口径（附录）
```

这条逻辑回答六个问题，顺序不能反：

1. **是什么**：产品定义、问题域、边界。
2. **给谁用**：角色、任务、现有替代方案。
3. **凭什么成立**：产品形态、核心价值链路、护城河。
4. **具体做什么**：五步流程与四段能力。
5. **怎么实现**：架构、证据链、数据契约、评测。
6. **用在哪、怎么落地**：案例、场景矩阵、路线图、风险。

> AI 价值必须放在功能之前。否则读者会把 EquipLens 理解成“又一个 AI PPT 工具”，而不是“设计前期分析的生产线”。

## 4. 逐页规划

### P01｜封面

**页面标题**：EquipLens-AI 产品说明书  
**副标题**：面向工程车辆外观部件设计前期分析的可控报告生成系统

**页面任务**：在第一眼建立“设计分析工具”而非“通用 AI 工具”的定位。

**内容模块**
- 产品名、版本、日期、文档属性（对外 / 内部）。
- 一句话定义：输入设备类别与关注部件，输出可编辑的竞品分析报告。
- 一张真实车型图 + 技术取景框 + 色彩占比条，暗示“分析”而不是“生成”。
- 不使用口号式长句；封面只保留一个定义句。

**图示**：真实车型照片 + 取景框 / 色彩占比 / 局部裁切标记。

**表达要求**
- 封面副标题必须出现“工程车辆”“外观部件”“前期分析”“可编辑报告”四个关键词。
- 禁止使用“让设计师回到……”这类品牌口号作为主标题。

### P02｜文档导航

**页面标题**：目录与阅读说明

**页面任务**：让读者在 30 秒内知道文档结构、阅读路径与数字口径。

**内容模块**
1. 目录：章节、页码、每章一句话范围。
2. 阅读路径：决策者（01/03/07）、设计团队（01–04/06）、技术评审（03/05）。
3. 指标口径：

   - 实测（Measured）：已有评测集或单批实测数据，注明样本量。
   - 验收（Acceptance）：交付前必须满足的硬标准。
4. 版本与范围说明：本文描述产品设计意图与当前实现，不替代 PRD 与接口规范。

**图示**：不需要大图；用清晰的目录表 + 口径说明框。

**表达要求**
- 删除“一份说明书，七个问题”这类无效设问。
- 目录只写章节名与范围，不写情绪化导语。

### P03｜01 产品概述（严格 1 页）

**页面标题**：产品定义：面向设计前期分析的可控报告生成系统

**页面任务**：一页回答“是什么、解决什么问题、边界在哪”。

**内容模块**
1. **一句话定义**
   - 输入：设备类别、关注部件、竞品范围、页数预算。
   - 处理：关联推荐 → 内容获取 → 结构化分析 → 版面生成。
   - 输出：可编辑的竞品分析报告（PPTX 为主，PDF 为辅）。
2. **问题域：前期分析的成本结构**
   - 素材获取与整理：来源散、无分类、质量参差。
   - 专业分析：部件识别、形态/CMF/意图描述依赖经验。
   - 版面生产：一车一页重复排版，修改牵动整页。
   - 知识沉淀：结论散落在历史报告，无法复用。
   - 每一项用“成本类型”描述，不用情绪化形容词。
3. **产品边界**
   - 做：竞品与部件级分析、清单与页序规划、可编辑版面、来源可追溯。
   - 不做：第一轮造型方案、替代设计师判断、整页贴图、无证据结论。
4. **成功标准（3 个）**
   - 报告制作周期：3–5 天 → ≤1 天（目标）。
   - 单车页直接采用率：≥60%（目标）。
   - 导出元素可编辑率：100%（验收）。

**图示**：输入 → 处理 → 输出 → 边界的四段式产品范围图。

**证据/数据**：PRD v1.0、真实样例报告、项目复盘。

**表达要求**
- 标题必须是定义句，不用“一份报告正在消耗……”这类叙事句。
- 一页内完成，不展开用户与功能细节。

### P04｜02 用户与场景（严格 1 页）

**页面标题**：用户与任务：谁在设计前期需要这份报告

**页面任务**：一页回答“谁在用、在什么任务里用、现在怎么凑合”。

**内容模块**
1. **角色表**
   - 主要用户：工业设计师 / 造型设计师。
   - 次要用户：设计管理、前期调研、售前方案。
   - 读者：企业客户评审人。
   - 每个角色写“任务 / 关注点 / 成功标准”，不写虚构姓名与年龄。
2. **核心 JTBD（3 条）**
   - 当新车型立项时，快速形成可讨论的竞品风格边界。
   - 当素材只有零散照片时，把可用图找出来、归好类、标好来源。
   - 当向客户汇报时，拿到一份版式专业、可当场修改的分析初稿。
3. **现有替代方案与不足**
   - 人工 + 通用网页 AI：能生成文字，但不理解部件、版式与证据。
   - 图库 + 人工整理：素材多，但分析与报告仍靠人。
   - 通用 AI PPT：能排版，但不具备竞品清单、证据链与设计分析 schema。
4. **使用场景（3 个）**
   - 新车立项竞品对标。
   - 单部件专项分析。
   - 汇报前资料准备与历史项目复用。

**图示**：角色—任务—关注点矩阵，或“用户任务链”简图。

**表达要求**
- 删除“用户不是想用 AI，而是明天要交报告”这类口语化标题。
- 用“任务 / 约束 / 成功标准”描述用户，不用情绪和虚构故事。

### P05｜03.1 产品形态：混合编排

**页面标题**：产品形态：workflow 骨架 + agent 关节的混合编排

**页面任务**：明确回答“我们是 Agent、Workflow，还是混合编排”，并解释为什么。

**内容模块**
1. **结论先行**
   - 不是通用 Agent，也不是纯 Workflow。
   - 是 **Agent-augmented workflow（混合编排）**：固定骨架保证可交付，关节处由模型判断，确定性护栏保证合规与可回退。
2. **三层结构**
   - 固定骨架（Workflow）：阶段、检查点、schema、渲染、账本、robots/配额。
   - 模型关节（Agent）：意图解析、关联扩展、查询规划、来源选择、相关性判定、停止/重查。
   - 确定性护栏（Guardrails）：证据门槛、页面模型校验、预算、人工确认、可回退。
3. **为什么不是纯 Agent**
   - 输出是交付物，不是聊天结果；必须可审计、可复现、可回退。
   - 成本与时延需要可控；不能每次让模型自由规划全流程。
   - 合规边界（robots、来源、客户素材）不能交给模型自由裁量。
4. **为什么不是纯 Workflow**
   - 长尾类目、语义歧义、证据缺口需要判断。
   - 固定规则覆盖不了“沙漠牵引车应该看哪些相邻车型”这类问题。
5. **产品判断**
   - 越接近“判断”，越交给模型；越接近“交付”，越写死。
   - 模型能力不是产品形态，**可审计的交付链路**才是。

**图示**：三层混合编排图（固定骨架 / 模型关节 / 确定性护栏），标注哪些环节由谁负责。

**证据/数据**：架构研讨稿 v0.2、模块清单 L0–L6、workflow/agent 分层结论。

**表达要求**
- 标题直接给出产品类型，不用比喻。
- 必须出现“Agent-augmented workflow / 混合编排”这一组术语，并在首次出现时解释。

### P06｜03.2 四段核心价值链路

**页面标题**：核心价值：从关联推荐到可编辑版面的四段链路

**页面任务**：把“我们到底提供了什么价值”讲成一条链，而不是四个功能。

**内容模块**
1. **关联推荐（L1.5）**
   - 输入：类目 + 部件 + 页数预算。
   - 能力：同类目 / 邻近类目 / 同平台 / 环境特化四轴扩展；推荐 / 方向级 / 备选分层；E3/E1 证据。
   - 输出：有限页数内可执行的竞品清单。
   - 领域知识：车型分类、平台关系、工况与部件的关联。
2. **内容获取**
   - 文本与图片多通道检索；用户上传兜底。
   - 门卫、视角判定、质量分、同设备聚类、来源记录。
   - 输出：每台车“可用主图 + 部件图 + 来源”的素材池。
3. **结构化分析**
   - 三维度：结构信息、设计信息、设计意图。
   - 部件级字段：名称、族属、形态、CMF、bbox、来源视图。
   - 领域知识：部件词表、造型语言、比例、分块分缝、品牌家族。
   - 输出：`analysis.json`。
4. **版面交付**
   - 页面模型（Page IR）：槽位、素材、文案、样式、来源。
   - 模板渲染：PPTX / PDF / HTML。
   - 输出：可编辑、可回退、可追溯的报告。

**图示**：四段链路图，每段标注“输入 / AI 动作 / 领域知识 / 输出物”。

**证据/数据**：关联清单样例、图片门卫单批数据、单车页真实截图、Page IR。

**表达要求**
- 每段必须写“领域知识”一栏，否则会退化成通用 AI 能力介绍。
- 不写“AI 很强大”，只写“AI 在哪一段替代了什么劳动，产物是什么”。

### P07｜03.3 护城河与商业化对比

**页面标题**：护城河：领域 schema、证据基础设施与修正数据

**页面任务**：回答“与商业化的 Agent 编排相比，优势在哪、壁垒在哪”。

**内容模块**
1. **对比表：通用 Agent / 通用 AI PPT / 图库+人工 / EquipLens**

| 维度 | 通用 Agent 编排 | 通用 AI PPT | 图库 + 人工 | EquipLens |
|---|---|---|---|---|
| 领域对象 | 通用文档/网页 | 通用幻灯片 | 图片 | 车型、部件、CMF、页型 |
| 任务边界 | 开放 | 开放 | 人工 | 前期分析报告，边界清晰 |
| 检索质量 | 通用搜索 | 弱 | 人工找图 | 多通道检索 + 门卫 + 证据分级 |
| 输出物 | 文本/动作 | 幻灯片 | 素材 | 可编辑分析页 + 报告 |
| 质量保证 | 靠 prompt | 靠模板 | 靠人 | 闸门 + 评测 + 检查点 |
| 成本/时延 | 不可预测 | 低 | 高 | 固定骨架，成本可测 |
| 数据资产 | 不留存 | 不留存 | 素材库 | 结构化沉淀 + 修正数据 |

2. **护城河拆解**
   - 领域 schema：分析三维度、部件词表、页型、品牌家族。
   - 证据基础设施：E3/E1、闸门、来源索引、可回放。
   - 修正数据：设计师在裁框、改词、调版式时留下的偏好数据。
   - 模板资产：母版、版式规则、品牌适配。
   - 评测集：把“好”定义成可回归的指标。
3. **商业化优势**
   - 单份报告成本可测、可优化；不是按 token 盲烧。
   - 时延可预期；适合嵌入设计流程与客户交付节点。

**表达要求**

## 6. 语言规范

### 6.1 总体要求

1. **标题即结论**：每页标题是一个可被验证的判断，不是设问、不是对话、不是口号。
2. **先定义，后论证**：首次出现的术语给定义；不要用形容词代替定义。
3. **一段一个论点**：每段首句是论点，后面跟证据或解释。
4. **数字带口径**：目标 / 实测 / 验收；实测必须带样本量与日期。
5. **少用比喻**：每页最多一个比喻，且不能替代论证。
6. **不用拟人化 AI**：不写“AI 理解设计师”“AI 替你想”，写“模型输出什么字段、系统如何校验”。
7. **不用设问句**：不写“为什么需要……”“你是否……”；直接给判断。
8. **口号限量**：封面/结语最多一句品牌表达，正文不出现口号。

### 6.2 标题改写示例

| 现有表达 | 问题 | v2 改写 |
|---|---|---|
| 一份说明书，七个问题 | 无效设问，信息量为零 | 目录与阅读说明 |
| 用户不是“想用 AI”，而是“明天要交报告” | 口语化、情绪化，像营销文案 | 用户与任务：谁在设计前期需要这份报告 |
| AI 不替设计师做决定。它把决定之前的工作做完。 | 拟人化口号，论证弱 | 产品形态：workflow 骨架 + agent 关节的混合编排 |
| 价值不在“生成”，在“可确认、可修改、可追溯” | 排比口号，信息密度低 | 核心价值：从关联推荐到可编辑版面的四段链路 |
| 质量不来自“更会写”，来自“证据够不够” | 对比式口号 | 检索与证据链：从查询规划到闸门与回放 |
| 把不确定性关在关节里，把确定性写进管线 | 文学化表达 | 技术架构：分层编排与确定性管线 |
| 让设计师回到判断与创意 | 品牌口号，不适合作为正文标题 | 结语可用一句；正文改为“AI 承担可标准化劳动，设计师负责定调与验收” |

### 6.3 推荐术语

- 产品层：产品定义、问题域、用户角色、JTBD、价值主张、产品形态、混合编排、护城河、交付契约、适用边界。
- 业务层：前期分析、竞品清单、单车页、部件专项、品牌家族、页序、页槽。
- 技术层：Agent-augmented workflow、workflow 骨架、模型关节、确定性护栏、证据等级、闸门、Page IR、analysis schema、run ledger。
- 设计分析层：形态、构型、比例、分块分缝、CMF、设计意图、部件族属、风格关键词。
