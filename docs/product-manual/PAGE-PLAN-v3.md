## 1. 页面逻辑

```text
封面
  → 01 产品定义（用在哪个环节、解决什么问题、边界）
  → 02 用户与现状（谁在做、现在怎么做、哪里卡住）
  → 03 核心价值（为什么值得换一种做法）
  → 04 产品形态（为什么是混合编排，而不是纯 Agent / 纯 Workflow）
  → 05 护城河与商业化（与通用 Agent / AI PPT / 图库+人工的差异）
  → 06 核心能力（关联推荐 → 内容获取 → 结构化分析 → 单车页 → 审校导出）
  → 07 技术实现（架构、证据链、数据管线、评测）
  → 08 场景验证（案例、场景矩阵）
  → 09 边界与质量（风险、承诺、合规）
  → 封底
```

逻辑要求：

- **先定义问题，再讲价值**：读者必须先知道“报告用在哪”，否则后面的能力没有判断标准。
- **先讲价值，再讲形态**：先让读者看到“省什么、强在哪”，再解释“为什么用混合编排实现”。
- **先讲护城河，再讲能力**：能力页是护城河的证据，不是功能清单。
- **每页一个判断**：标题就是结论；正文只给证据、边界与产物。

### P02｜01 产品定义：报告用在项目哪个环节

**页面标题**：产品定义：设计前期的竞品分析报告

**页面任务**：一页回答“这份报告用在哪个环节、解决什么问题、边界在哪”。

**内容模块**
1. **项目阶段图**
   - 项目立项 → **设计前期分析（本产品）** → 第一轮造型方案 → 方案评审。
   - 明确：报告发生在第一轮造型方案之前，不是造型方案本身。
2. **使用环节**
   - 外观部件迭代项目的设计前期；项目启动后、造型方案开始前。
   - 由设计团队制作，向合作企业客户（国企为主）汇报前期看法。
3. **报告目的**
   - 对齐设计风格与设计边界。
   - 让客户在进入第一轮造型前，对竞品格局、部件做法、CMF 方向形成共同判断。
   - 不包含第一轮造型方案。
4. **输入 / 输出**
   - 输入：设备类别、关注部件、竞品范围、客户资料、素材。
   - 输出：可编辑的竞品分析报告（PPTX 为主，PDF 为辅）。
5. **边界与成功标准**
   - 做：竞品与部件级分析、清单与页序、可编辑版面、来源可追溯。
   - 不做：造型方案、替代设计师判断、整页贴图、无证据结论。
   - 成功标准：3–5 天 → ≤1 天（目标）；单车页直接采用率 ≥60%（目标）；导出元素可编辑率 100%（验收）。

**图示**：项目阶段时间轴 + 输入/输出/边界三栏。

**证据/数据**：PRD §1.1、§4 核心业务流程；真实样例报告。

**表达要求**
- 第一段必须直接写“用在哪个环节”，不要先讲行业背景。
- 不写“AI 赋能设计”这类空话。

### P03｜02 用户与现状：现有生产流程

**页面标题**：用户与现状：前期分析报告的现有生产流程

**页面任务**：一页写清“谁在做、现在怎么做、哪里卡住”，全部基于项目已有资料，不写虚构人物。

**内容模块**
1. **角色**
   - 主责：工业设计师 / 造型设计师。
   - 协同：设计管理、前期调研、售前方案。
   - 评审：企业客户（国企为主）。
2. **现状行为（6 步）**

| 阶段 | 现状动作 | 工具 / 协作 | 主要问题 |
|---|---|---|---|
| 接需求 | 明确设备类别、竞品范围、关注部件 | 项目会 / 客户输入 | 口径模糊，竞品边界靠经验 |
| 找素材 | 甲方提供 + 展会拍摄 + 网络收集 | 搜索引擎、图库、聊天记录 | 图散、背景乱、质量参差 |
| 整素材 | 人工筛选、去重、按车型/视角/部件归类 | 文件夹、PS、肉眼 | 耗时；型号识别靠人；缺主图 |
| 读图分析 | 看造型、色彩比例、部件、CMF，写分析 | PPT / Word / 通用网页 AI | 依赖个人经验，口径不统一 |
| 排版 | 一车一页，套母版，复制图文 | PowerPoint / WPS | 重复劳动；改字牵动整页 |
| 评审返工 | 内部评审、客户汇报、反复修改 | 邮件 / 会议 / PPT | 修改不可定位；版本散落 |
| 沉淀 | 报告留在个人电脑或历史项目 | 个人文件夹 | 下个项目从零开始 |

3. **现有替代方案与不足**
   - 人工 + 通用网页 AI：能写文案，但不理解部件、版式、证据。
   - 图库 + 人工整理：素材多，但分析与报告仍靠人。
   - 通用 AI PPT：能排版，但没有竞品清单、证据链与设计分析 schema。
4. **结论**
   - 现状不是“没有工具”，而是“工具各自为战，报告仍然靠人拼接”。

**图示**：现状流程图（6 步）+ 每步卡点标记。

**证据/数据**：PRD §3 用户画像与典型场景、§4 核心业务流程；`web-interaction-spec.md` 的五步流程与现状描述。

**表达要求**
- 不写姓名、年龄、虚构对白；用“角色—动作—工具—问题”。
- 不把现状写成“用户很痛苦”，写“哪一步消耗了什么、为什么难复用”。

### P04｜03 核心价值：一条可确认、可编辑、可追溯的生产线

**页面标题**：核心价值：把前期分析从个人经验驱动变成可复用的生产线

**页面任务**：先让读者看到价值，再进入产品形态与能力。

**内容模块**
1. **价值主张**
   - 对工业设计师：把找图、整图、写分析、排版这些可标准化的劳动交给系统，把判断与客户沟通留给人。
   - 对设计管理：报告结构、来源、版本可检查，减少“靠个人经验”的波动。
   - 对客户：汇报材料图文专业、结论有出处、可当场讨论修改。
2. **四个价值点**

| 价值 | 现状 | 目标 / 验收 |
|---|---|---|
| 效率 | 3–5 天做一份 10–15 台竞品报告 | ≤1 天（目标） |
| 单车分析 | 人工读图、写文案、排版 | 20–40 秒 / 车（MVP 目标） |
| 质量 | 依赖个人经验，口径不一 | 部件命中 ≥85%、描述评分 ≥4/5（目标） |
| 可控 | 修改不可定位，版本散落 | 100% 元素可编辑、来源可追溯（验收） |

3. **价值实现方式（一句话）**
   - 不是“让 AI 写一篇报告”，而是把报告拆成清单、素材、分析、页面四个可确认的对象。
4. **边界**
   - 价值成立的前提：有 10 台左右可用竞品素材、关注部件明确、客户接受“可编辑初稿”而非“一次成稿”。

**图示**：四象限价值图，或“现状 → 目标”的对照表 + 一条四段链路预告。

**表达要求**
- 这一页只讲价值，不讲架构、不讲模型。
- 数字必须标目标 / 验收，不把目标写成实测。

### P05｜04 产品形态：workflow 骨架 + agent 关节的混合编排

**页面标题**：产品形态：workflow 骨架 + agent 关节的混合编排

**页面任务**：明确回答“我们是 Agent、Workflow，还是混合编排”，并解释为什么。

**内容模块**
1. **结论**
   - 不是通用 Agent，也不是纯 Workflow。
   - 是 **Agent-augmented workflow（混合编排）**：固定骨架保证可交付，关节处由模型判断，确定性护栏保证合规与可回退。
2. **三层结构**

| 层 | 负责什么 | 具体内容 |
|---|---|---|
| Workflow 骨架 | 保证可交付 | 阶段、检查点、schema、渲染、账本、robots/配额 |
| Agent 关节 | 处理长尾判断 | 意图解析、关联扩展、查询规划、来源选择、相关性判定、停止/重查 |
| 确定性护栏 | 保证合规与可回退 | 证据门槛、预算、页面模型校验、人工确认 |

3. **为什么不是纯 Agent**
   - 输出是交付物，必须可审计、可复现、可回退。
   - 成本与时延要可控；不能每次让模型自由规划全流程。
   - 合规边界不能交给模型自由裁量。
4. **为什么不是纯 Workflow**
   - 长尾类目、语义歧义、证据缺口需要判断。
   - 固定规则覆盖不了“沙漠牵引车应该看哪些相邻车型”这类问题。
5. **判断原则**
   - 越接近“判断”，越交给模型；越接近“交付”，越写死。
   - 模型能力不是产品形态，**可审计的交付链路**才是。

**图示**：三层混合编排图（骨架 / 关节 / 护栏），标注每层负责的环节。

**证据/数据**：架构研讨稿 v0.2、模块清单 L0–L6、workflow/agent 分层结论。

**表达要求**
- 必须出现“Agent-augmented workflow / 混合编排”术语，首次出现时解释。
- 不写“我们也是 Agent”这种模糊表述。

### P06｜05 护城河与商业化

**页面标题**：护城河与商业化：领域 schema、证据基础设施与修正数据

**页面任务**：回答“与商业化的 Agent 编排相比，优势在哪、壁垒在哪”。

**内容模块**
1. **对比矩阵**

| 维度 | 通用 Agent 编排 | 通用 AI PPT | 图库 + 人工 | EquipLens |
|---|---|---|---|---|
| 领域对象 | 通用文档/网页 | 通用幻灯片 | 图片 | 车型、部件、CMF、页型 |
| 任务边界 | 开放 | 开放 | 人工 | 前期分析报告，边界清晰 |
| 检索质量 | 通用搜索 | 弱 | 人工找图 | 多通道 + 门卫 + 证据分级 |
| 输出物 | 文本/动作 | 幻灯片 | 素材 | 可编辑分析页 + 报告 |
| 质量保证 | 靠 prompt | 靠模板 | 靠人 | 闸门 + 评测 + 检查点 |
| 成本/时延 | 不可预测 | 低 | 高 | 固定骨架，成本可测 |
| 数据资产 | 不留存 | 不留存 | 素材库 | 结构化沉淀 + 修正数据 |

2. **护城河五层**
   - 领域 schema：分析三维度、部件词表、页型、品牌家族。
   - 证据基础设施：E3/E1、闸门、来源索引、可回放。
   - 修正数据：设计师裁框、改词、调版式留下的偏好数据。
   - 模板资产：母版、版式规则、品牌适配。
   - 评测集：把“好”定义成可回归的指标。
3. **商业化优势**
   - 成本可测：单份报告成本可核算、可优化。
   - 时延可预期：适合嵌入设计流程与客户交付节点。
   - 可审计：满足企业客户对来源与合规的要求。
   - 可集成：输出 PPTX/PDF/HTML，不锁定工作流。
4. **什么不是护城河**
   - 模型本身、单点 prompt、一次性功能；这些会随通用能力商品化。

**图示**：对比矩阵 + 五层资产堆叠图。

**表达要求**
- 不贬低竞品，用“适用边界不同”而不是“他们不行”。
- 护城河必须落到资产，不落到“团队更懂设计”。

### P07｜06.1 关联推荐：页数受限的竞品清单

**页面标题**：关联推荐：把类目与部件要求转成页数受限的竞品清单

**页面任务**：证明“找什么车”是可解释、可审计的，而不是拍脑袋。

**内容模块**
1. **为什么难**
   - 长尾类目没有完整名录；型号边界模糊；样本不足。
   - 工程车辆的“同类”不只是车型名，还涉及平台、构型、工况、部件。
2. **四轴扩展**
   - 同类目：同车型类别、同品牌家族。
   - 邻近类目：用途相近、构型相近。
   - 同平台：6×4 / 6×6 / 8×8、驾驶室平台、底盘平台。
   - 环境特化：沙漠、矿区、高原、寒区。

## 5. 语言与内容规范

1. **标题即结论**：不写设问句、对话句、排比口号；标题是一个可验证的判断。
2. **先定义，后论证**：首次出现的术语给定义；不用形容词代替定义。
3. **一段一个论点**：首句是论点，后面跟证据或解释。
4. **数字带口径**：目标 / 实测 / 验收；实测必须带样本量与日期。
5. **不用拟人化 AI**：不写“AI 理解设计师”“AI 替你想”，写“模型输出什么字段、系统如何校验”。
6. **结合工程车辆术语**：形态、比例、分块分缝、CMF、设计意图、品牌家族、部件族属。
7. **结合 AI 产品术语**：Agent-augmented workflow、workflow 骨架、模型关节、确定性护栏、证据等级、Page IR、run ledger。
8. **不写部署/路线图**：全文不出现单机、云端、4C8G、start.bat、P0–P3 路线图。
9. **口号限量**：封面/结语最多一句；正文不出现品牌口号。
10. **现状行为写法**：角色—动作—工具—问题，不写虚构人物故事。

**标题改写方向**

| 旧类型 | 新方向 |
|---|---|
| 设问式目录标题 | 删除；封面后直接进入产品定义 |
| 对话式用户标题 | 用户与现状：前期分析报告的现有生产流程 |
| 排比式价值标题 | 核心价值：把前期分析变成可确认、可编辑、可追溯的生产线 |
| 文学化技术标题 | 技术架构：分层编排与确定性管线 |
| 口号式结尾 | 边界与质量：已知风险、对策与承诺 |
