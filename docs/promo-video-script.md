# EquipLens 宣传片 · 解说脚本（v1）

- 类型：**解说片**（科普口吻，不是品牌大片）
- 时长：约 **135 秒**
- 结构：问题 → 产品 → 三个后台步骤（检索 / 关联推荐 / 图筛选）→ 结构化 → 交付 → 落版
- 旁白：默认**用旁白**（解说片以解说为骨架）；若不做人声，用同文大字字幕 + 音乐

## 1. 解说词与画面（逐段）

### 1｜问题（0–10s）
> 做一份重卡竞品分析，设计师通常要花两周：搜图、截图、量比例、再拼成 PPT。

**画面**：夜里的一块屏幕，浏览器标签页一个个亮起又堆叠；一个"竞品截图"文件夹滚动，缩略图刷成一片。
**素材**：真人素材 1 段（可选）｜或纯代码：标签页墙 + 文件列表。
**要点**：不嘲笑谁，只说事实。

### 2｜产品是什么（10–22s）
> EquipLens 只需要你说清两件事：看什么设备，看哪些部位。剩下的它自己做。

**画面**：真实界面。输入「沙漠牵引车」，部位框里敲入六个词，回车。镜头推近到输入行。
**素材**：真实录屏切片（我们有 146s 的完整录屏）。
**字幕**：`一类设备 ＋ 若干部位 → 一份竞品分析`

### 3｜检索：从文字里找车（22–48s）
> 第一步不是搜图，是搜人写过的文字。
> 二十多篇文章里，真正提到具体车型的只是一部分。系统把品牌和型号从标题和正文里抽出来，再按被提到的次数排序——被反复提到的，才是这个类目里真正的对手。

**画面**（三层递进，全是代码特效）：
1. 文字墙：20+ 篇文章的标题与摘要落下，铺满画面，可读但拥挤
2. 高亮抽取：型号词逐个高亮（`德龙X3000`、`JH6`…），被"吸"出成标签，飞向右侧
3. 合并排序：同名标签叠在一起，计数 +1，柱状高度随提及次数增长

**素材**：真实检索结果（`data/web-runs/*/` 下的候选与来源标题）
**效果**：高亮扫描线、标签飞入、计数滚动——都对应真实数据

### 4｜关联推荐：为什么是这几台（48–78s）
> 推荐不是拍脑袋。每一台车都要回答三个问题：
> 它和这个类目是什么关系？依据在哪篇文章？那篇文章是怎么说的？
> 把这三个问题串起来，就是一条可以逐条核对的推理链——所以清单里每一行，都带着它的来源。

**画面**（推理链，逐步点亮）：
1. 中心：搜索词「沙漠牵引车」
2. 第一圈：5 篇文章节点依次亮起，连线到中心
3. 第二圈：从文章节点连出车型节点（陕汽德龙、德龙6X6、东风天锦…）
4. 每条连线末端浮出**关系标签**：同类目 / 邻近类目 / 平台共用 / 环境特化
5. 最后一步：连线收拢成一行结论——`德龙 X3000 · 同类目 · 依据：8 篇文章提及`

**素材**：真实的候选清单与关联理由 JSON
**效果**：节点生长、连线描绘、标签浮现；结论行从上一步"长"出来

### 5｜门卫：图片怎么筛（78–102s）
> 搜来的图大部分不能用：有的是乘用车，有的是局部特写，有的和型号对不上。
> 系统给每张图打一个分，再用类别和型号做二次校验，最后按视角排序。十张里，通常只留下两三张。

**画面**：
1. 图片墙涌入（12 张），每张下方出现分数条
2. 不合格的：分数条变红 → 图片变灰 → 被推出画面（逐个，非同时）
3. 合格的：边框亮起 → 浮出视角标签（front / side）
4. 留下的三张排成一行

**素材**：真实爬取图 + 真实门卫 margin + 视角判定结果
**效果**：分数条增长、判定闪烁、推离动画

### 6｜结构化分析（102–120s）
> 留下的图会拆成六个部位。每个部位回答四件事：
> 它是什么构型、属于哪一族、形态怎么描述、材料和颜色是什么。
> 这些不是形容词，是能跨车对比的结构化数据。

**画面**：照片上六个 bbox 依次画出（每个 0.4s）；右侧四槽卡片逐条写入：`构型 / 族 / 形态 / CMF`；最后三词浮出。
**素材**：真实分析 JSON（bbox、term、family、form、cmf、style_tags）
**效果**：框线描绘、文字逐字机打、字段高亮

### 7｜交付（120–132s）
> 最后一步是排版。框不对可以改，字可以改；导出的 PPT 里，每个元素都能编辑。

**画面**：裁框页（拖一个框）→ 页面逐页翻 → 十页叠起 → 导出按钮 → PPT 图标。
**素材**：真实录屏 + 页面截图

### 8｜落版（132–138s）
> EquipLens：把竞品分析，做成十分钟。

**画面**：Logo（齿轮+放大镜）被推入画面中央，字标擦出；下方一行网址。
**素材**：自有 SVG

## 2. 每个"特效"对应哪份真数据

| 段落 | 画面元素 | 数据来源 |
|---|---|---|
| 3 | 文章标题、型号抽取、提及次数 | `data/web-runs/<run>/` 候选 JSON 的 sources |
| 4 | 关系标签、依据句、排序 | 候选 JSON 的 `relation` / `reason` / `mentions` |
| 5 | 图片、分数、视角 | 门卫 `margin`、`view`、`gated_out` |
| 6 | bbox、四槽、三词 | 分析 JSON 的 `parts[]`、`unit.style_tags` |
| 7 | 页面、裁框 | 真实页面 HTML + 裁框页 |

> 没有任何一个数字是编的；演示里出现的车、图、分数都来自同一次真实运行。

## 3. 仍需你定

1. **旁白怎么做**：真人配音 / 本地 TTS（免费，机器味）/ 只有字幕+音乐
2. **时长**：135 秒（上表）；要更短就砍第 1 段和第 5 段的细节
3. **要不要真人素材**：第 1 段那个"深夜桌面"，用真人素材还是纯代码模拟

## 4. 与上一版的区别

上一版（`promo-video-plan.md`）是品牌片思路：讲一个故事、靠氛围。这一版是**解说片**：每一段都在回答一个具体问题，画面是**论证**不是氛围——这也是你要的"直观展示后台在做什么"。
