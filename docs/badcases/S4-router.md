# S4 Router：badcase 明细（100 条盲测暴露）

> 上游：[`README.md`](README.md)。输入均为测试数据（`[test]`）。
> 数据：`data-test/evals/router-holdout100-20261116.jsonl`（子代理盲写，未参与调参）。

## BC-S4-001（显式总数被降级为增量的误判）

- **状态**：open（规则/守卫问题）
- **触发**：`每个车型从4张调到6张`、`两台车一共要20张图`、`豪沃那个凑够10张吧`
- **期望**：`plan.quantity`（显式总数/总量）
- **实际**：`fill.quota`
- **根因**：守卫把“凑/再加”一律降级为增量；没有区分“凑够 N（总量）”与“再加 N（增量）”。
- **下一步**：口径先定（见下）；守卫增加“显式总数”判定，不按类目特判。
- **关联**：BC-S05-002/006。

## BC-S4-002（质量诉求被标成排除项）

- **状态**：by-design（我们的口径：质量=quality）
- **触发**：`别给我带水印的图`、`不要手机拍的`、`图片别压缩，要原图`
- **期望（我们的口径）**：`fetch.filters.quality`
- **holdout 标注**：`plan.negative` → **标注口径分歧**，不是识别错误。
- **下一步**：写进 router 标注口径；重标 holdout。

## BC-S4-003（部件请求漏识别）

- **状态**：open
- **触发**：`我想看底盘和悬挂那块，最好能看清大梁和钢板弹簧，有这种图吗`
- **期望**：`fetch.parts`；**实际**：空目标（clarify）。
- **根因**：部件词不在既有 `fetch.parts` 触发集内（底盘/悬挂/大梁/钢板弹簧）。
- **下一步**：按“关注具体部件”的语义补 few-shot/动作定义，不建部件词表。

## BC-S4-004（多意图漏项）

- **状态**：open
- **触发**：`第5张太模糊了，重新找一张补上，原来那张别用了`、`只要沙漠版，普通版不要了`、`都删了重新来吧`
- **期望**：2 个目标（替换+拉黑 / 范围+排除 / 删除+重置）；**实际**：只出 1 个或类型偏。
- **根因**：LLM 倾向给单一 target；守卫未强制“多意图拆分”。
- **下一步**：prompt 明确“一句多意图最多 2 个 target”，守卫保留。

## BC-S4-005（破坏性 hard/soft 口径）

- **状态**：product-decision（需拍板）
- **触发**：`第4张换成高清原图`、`把那个换掉`、`第一张是渲染图…拉掉`
- **冲突**：holdout 标 hard/`verify.blacklist`，我们按 BC-S05-003 判 soft/`delivered.replace`。
- **下一步**：写进标注口径；若产品坚持“明确目标也 hard”，改守卫与坏例。

## BC-S4-006（缺“能力/可行性”层，越界请求被硬映射）

- **状态**：**P0 已修**（capability gate + explain；2026-11-16）
- **触发**：`别给我带水印的图`、`导出的图别压缩，要能印刷`、`不要那种灰蒙蒙的阴天图`、
  `帮我写个周报吧`
- **现象**：被映射到 `fetch.filters.quality` / `delivery.report` 等“最近的 action”，
  但系统并没有去水印、印刷级导出、天气筛选、写周报的能力。
- **根因**：router 只有“动作分类”，没有“我们能不能做”的能力判定；越界请求被伪装成可执行动作。
- **下一步**：加 capability gate（支持/不支持/部分支持），不支持时返回说明 + 可做什么，**不产生 patch**。

## BC-S4-007（缺“阶段”维度）

- **状态**：**P0 已修**（stage gate；2026-11-16）
- **触发**：`第4张换成高清原图`（交付后）、`8x8的不要，我只要6x6`（输入中补构型）、
  `第5张太模糊了，重新找一张补上`（看到结果后）
- **现象**：同一句话在不同阶段含义不同，但 router 没有 stage 输入，只有弱 context；
  输入阶段出现“第 N 张”、交付前出现“换图”都会被误读。
- **下一步**：router 输入加 `stage`（pre_run / running / delivered），按阶段限制可用 action；
  交付前不允许 `delivered.*`/`verify.blacklist`（无资产可指）。

## BC-S4-008（数量语义未建模）

- **状态**：**P1 部分修复**（新增 per-model；fill.quota 限定同车；补抓仍 best-effort）
- **触发**：`每个车型统一按6张来`、`每个车型从4张调到6张`、`德龙X3000要8张，现在才4张`、
  `豪沃那个凑够10张吧`、`两台车一共要20张图`
- **现象**：四种不同语义被塞进 `plan.quantity` / `fill.quota`：
  ① 总量；② 每款张数；③ 同一台车再加图；④ 条件扩张（每款补到 N）。
  用户口径：**“同款补图”只应在“同一台车要更多图”时触发**，其他增数量应算改总数。
- **下一步**：明确四个动作/字段，至少新增“每款张数”语义；不要在 `fill.quota` 里混总量。

## BC-S4-009（复合意图只出一个 target）

- **状态**：**fixed**（P2，2026-11-16；prompt 多动作 + 三条组合守卫 + 选项化澄清）
- **触发**：`驾驶室要高顶的，平顶的不要`（排除 + 范围 + 补总数）、
  `只要沙漠版，普通版不要了`（范围 + 排除）、`第5张太模糊了，重新找一张补上，原来那张别用了`
  （替换 + 拉黑）
- **现象**：只输出一个 target，另一层意图丢失。
- **下一步**：prompt/守卫支持“一句最多 2–3 个动作 + 顺序”，并校验“多意图是否被拆开”。

## BC-S4-010（构型替换 + 补型号未拆全）

- **状态**：open（2026-11-16 用户审核 #17）
- **触发**：`8x8的不要，我只要6x6`
- **用户口径**：这是**输入阶段漏了构型、中途补**；应“删掉 8x8 的内容 + 补 6x6 特定型号的内容”。
- **实际**：`plan.configuration + plan.negative`（改了构型、排除了 8x8），**漏了补型号**（`plan.add_targets`）。
- **下一步**：在“构型替换”场景补“是否需要新增对应型号”的判定；属于 P2 后续小项，不单独开机制。

## BC-S4-011（界面功能被当成对话意图）

- **状态**：**fixed**（P3，2026-11-17；UI guide）
- **触发**：`导出成PPT`、`给我导个PDF`、`PPT在哪导出？`、`保存一下这个方案`
- **期望**：`action=guide` + 界面位置，不产生 patch。
- **实际（修复前）**：映射 `delivery.report` / `clarify` / `session.reset`。
- **修复**：UI_GUIDE 规则；直接提问和“指令式 UI 操作”都走 guide。

## BC-S4-012（暂停 + 附带修改只出暂停）

- **状态**：open（BL-019）
- **触发**：`先停一下，等我把品牌加上`（P3 B041）
- **期望**：`session.pause + plan.add_targets`，修改存 `pending_on_resume`。
- **实际**：只出 `session.pause`。
- **下一步**：实现 pause+edit 的拆分与恢复确认；已知 1/10 失败。

## BC-S4-013（构型 + 排除复合漏项）

- **状态**：open
- **触发**：`6x6不要了，全上8x8`（P3 A082）
- **期望**：`plan.configuration + plan.negative`。
- **实际**：只出 `plan.configuration`。
- **下一步**：构型切换同时出现“不要/别放”时补 negative；属复合守卫小项。

## BC-S4-014（部件召回：吊臂特写）

- **状态**：open
- **触发**：`吊臂特写要几张`（P3 A096）
- **期望**：`fetch.parts`；**实际**：clarify。
- **根因**：LLM 未把“吊臂”识别为部件；不建部件词表。
- **下一步**：用动作定义/示例补语义，不改词表。

## BC-S4-015（身份错但未指哪张）

- **状态**：product-decision（口径）
- **触发**：`这不是我要的那款，别放进来`（P3 C074）
- **期望（当前标签）**：`verify.blacklist`；**实际**：`delivered.remove`。
- **问题**：没有第 N 张，无法定位资产；应澄清“哪一张”，还是标黑整批？需产品定。

## BC-S4-016（hard 动作只记录、不执行）

- **状态**：**fixed（gate，2026-11-17）**
- **触发**：`数量改成12台`、`6x6换8x8`、`只看沙漠版`、`全部重来`、`先停一下`
- **现象**：Session 记录 patch/状态，但引擎没有对应分支；runner 也不检查 pause/reset。
  用户会以为已改，实际交付不变。
- **证据**：`engine.apply_patches` 只有 views/parts/quality/fill.quota/quantity_per_model/
  negative/add_targets；`session_runner.py` 无 pause/reset 处理。
- **下一步**：delta 前先 gate 为 clarify/explain，或实现重排/重跑；不能继续静默记录。
