## 2. 关键结论（30 秒版）

1. 现状流程是"人工 + 通用网页 AI"半自动；产品价值 = 流程产品化（闭集匹配、裁图、排版、溯源、合规）；
2. 车型识别重构为两阶段**闭集匹配**（名录 → 照片对号，靠外观特征而非仅 Logo），FR-1.1 验收口径需改；
3. 素材不足是常态 → FR-1.2 优先级上调；竞品集 = 同类 + 近似类目；
4. FR-3 特征线规格已具体化（3/4 前脸主图、降透明度底图、少量手描线）；
5. PRD 两处遗漏：封底、素材充分性评估；情绪版排期（P2）可能过于靠后；
6. 模块版图细化为五块：素材资产库 + 检索 + 分析整合 + 报告规划 + 排版；统一分析 schema（结构/设计/意图三维度）是四模块公共合同；
7. 知识沉淀走进化式（数据飞轮）：按统一 schema 每项目沉淀，存"确认过的事实与素材"而非现成答案；检索模块拟采用"对话为壳、结构化对象为核"混合交互（候选待确认）；
8. 部署形态定为**单机本地（SQLite + 文件系统）**；单车数据模型定稿：四层树（Vehicle/Facts/Descriptions/Asset）+ 描述三轴（节点×类型×范围）+ 完备度 L0–L3 派生不存储 + 三条不变量（可推导不存储 / 确认记录只增不改 / 原图不可变）；冗余收窄决议 S1–S5 见规范 §1；
9. 近似重复识别边界已实验厘清（2026-10-12）：dHash 全图指纹**抓不到"从另一张图裁出来"的图**（实验证实），滑动窗口区域匹配可精准定位裁剪来源（哈希距离 3/180 vs 随机中位 90）——该能力落位 P1.5（`region_match` 证据类型，schema 已预留），MVP 阶段裁剪图走人工确认；
10. M1–M3 整体 review（2026-10-12）：架构骨架与三条不变量无逻辑问题；发现 2 个状态联动边角漏洞（hero 指针不清理、undo 覆盖后续修改）待 M3.1 修复；确认"模块间只通过数据契约交换"机制可支持随时单开子专项（特征线/背景处理/铭牌识别/检索均可独立开发测试，各自自带合成评测集、走同一数据层）；
11. 检索模块调研（2026-10-14，详见 `docs/retrieval-tooling-research.md`）：四层栈均无需自研——渠道层 SearXNG 自建聚合、抓取层 Crawl4AI 自托管、图片层 img2dataset 思路 + Openverse 合规补充、编排层借 GPT-Researcher 范式自研轻量任务树；**图文对应 = 已有绑定证据体系在抓取阶段的延伸**（结构化抽取/页面共现/区域匹配复核/alt 加权四条链）；合规边界决策选项单（A/B/C，推荐 B：API 优先 + 受控抓取）待拍板。
