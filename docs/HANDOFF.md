## 2. 关键结论（30 秒版）

1. 现状流程是"人工 + 通用网页 AI"半自动；产品价值 = 流程产品化（闭集匹配、裁图、排版、溯源、合规）；
2. 车型识别重构为两阶段**闭集匹配**（名录 → 照片对号，靠外观特征而非仅 Logo），FR-1.1 验收口径需改；
3. 素材不足是常态 → FR-1.2 优先级上调；竞品集 = 同类 + 近似类目；
4. FR-3 特征线规格已具体化（3/4 前脸主图、降透明度底图、少量手描线）；
5. PRD 两处遗漏：封底、素材充分性评估；情绪版排期（P2）可能过于靠后；
6. 模块版图细化为五块：素材资产库 + 检索 + 分析整合 + 报告规划 + 排版；统一分析 schema（结构/设计/意图三维度）是四模块公共合同；
7. 知识沉淀走进化式（数据飞轮）：按统一 schema 每项目沉淀，存"确认过的事实与素材"而非现成答案；检索模块拟采用"对话为壳、结构化对象为核"混合交互（候选待确认）；
8. 部署形态定为**单机本地（SQLite + 文件系统）**；单车数据模型定稿：四层树（Vehicle/Facts/Descriptions/Asset）+ 描述三轴（节点×类型×范围）+ 完备度 L0–L3 派生不存储 + 三条不变量（可推导不存储 / 确认记录只增不改 / 原图不可变）；冗余收窄决议 S1–S5 见规范 §1。

## 3. 下一步（P1 素材资产库开发计划，按序执行）

目标：一批杂图进 → 自动落盘/判重/打标 → 人工确认 → 按视角/部位/完备度查询（FR-1.1 落地）。P1 全程 CLI/API 驱动，不开发 UI——界面等检索模块交互范式（"对话为壳、结构化对象为核"）一起设计，避免返工。

| 里程碑 | 内容 | 测试 | 成本 |
|---|---|---|---|
| M1 导入与判重 | 批量导入 → 解码尺寸 → sha256/感知哈希 → 原图落盘 → unbound 入库；哈希命中并入既有素材（同图多源 D5） | 判重/非法文件单元 + 重复导入集成 | 零 |
| M2 确认工作流 | 待确认列表 / 批量确认 / 改标 / 撤销 / 拒绝，全部走 confirm()/undo() | 工作流单元 + 重复确认与撤销链防护 | 零 |
| M3 查询接口补全 | 视角/部位/授权/质量过滤；"车型摘要"（完备度徽标+待确认数，渐进披露列表层接口） | 合成样例查询断言 | 零 |
| M4 VLM 自动打标 | 模型网关薄封装（国产 VLM 可切换，NFR-1）；输出约束过 schema，不合法重试→降级人工；计量留痕（新增 api_calls 表，NFR-2） | mock 网关单元测试（零成本）+ 10 张内真模型小批量验证 | 起产生 API 费用 |
| M5 评测集 v0 + 第二档 | 历史散图 30–50 张人工标答案建黄金集；跑 FR-1.1 验收指标（视图分类 ≥85% / 品牌型号 ≥90% / 模糊遮挡标记 ≥90%）；第二档全流程拟真校验 | 评测报告 v0 + 基线数字；此后 prompt/模型变更须过评测（NFR-8） | 需素材到位 |
| M6 收尾 | ingest 批处理 CLI、成本报表初版、使用文档 | 端到端演练 | 零 |
