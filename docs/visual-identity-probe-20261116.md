# S2-01 可行性探针：本地 CLIP 能否提供“视觉身份”证据（2026-11-16）

**结论：NO-GO。** 用项目现成的 UForm3（英文零样本）给 335 张已落盘候选图做
“真型号 vs 随机另一型号 vs 泛化 truck”三选一，top-1 只有 **11.0%**（随机 33.3%），
真模型 vs 随机模型的二选一准确率 **51.9%**（95% CI 46.6–57.2%，等于抛硬币）。
扣掉“标签文本天生更贴这类图”的先验偏置后仍是 **52.5%**；每型号只取一张图的去相关
子集是 **48.4%**。视觉身份不足以作为 VERIFY 的新证据来源，不建议接线。

- 代码：`scripts/probe_visual_identity.py`（只读 state.json/图片，只写一个 JSON）
- 产物：`data-test/evals/visual-identity-20261116.json`（335 条逐资产分 + 汇总）
- 全程离线：模型来自本机 HF 缓存（`~/.cache/huggingface/hub/models--unum-cloud--uform3-image-text-english-small`），无下载、无 LLM API。

## 1. 问题

VERIFY 现在只有文本侧证据（标题命中型号、构型、规则）。本探针只回答一个问题：
**同一套本地 CLIP 权重，能不能把“这张图是哪个型号”从文本标签里判出来？**
判不出来就不值得为它加一条视觉身份门槛。

## 2. 数据与标签来源

| 项 | 值 |
|---|---:|
| 扫描 | `data-test/runs/m43-*/state.json` 的 `asset_meta`，10 个 run（base + sess） |
| asset_meta 行 | 547 |
| 去重后有 image + 非空 `model` | **335**（按 asset_id 去重，base 优先于 sess） |
| 唯一型号标签 | **93**（含“悍马320/悍马 320 单钢轮…”这类同车异写） |
| 标签脚本 | 中文含 CJK 283；纯拉丁/数字 52 |
| 场景 | single_vehicle 158；part 173；multi_vehicle 4 |
| 已验收（代理） | 任一 part 验证 `accepted=true`：170；`model` 命中 `units[*].accepted_targets`：174 |
| 图片读取失败 / 内容重复 | 0 / 0（335 张 md5 全不同） |

**标签来源：`asset_meta[*].model`，即当时检索查询命中的目标名（`target_id` 同源），
不是人工核对的真值。** 它可能是品牌+型号+工况的长描述（如
“中联重科 ZBH5073TSUXE6 湿式扫路车”），也可能是 “C90”“EFL302” 这种代码。
这正是本次要报告的 label noise。

## 3. 方法

- 图像：UForm3 image encoder（ONNX CPU，256 维），单位向量；与门卫
  `src/equiplens/gate.py` 同一权重、同一预处理，不新增模型。
- 文本候选（统一模板 `a photo of a {label}`）：
  1. **true**：`asset_meta.model`
  2. **random**：从完整 93 个标签里按 `asset_id|random` 种子抽一个，排除同名
  3. **truck**：`a photo of a truck`（泛化对照）
- 附加对照 **same-category random**：从同 run（run 后缀当类目代理：desert /
  forklift / roller / wrecker / sweeper）里抽另一个型号，检验“同类目内还能不能分”。
- 指标：3 选 1 top-1；true-vs-random 二选一；Wilson 95% CI；margin =
  `sim_true − max(其余候选)`；按场景/标签脚本/query_tier/验收状态拆分；
  每型号只留一张图做去相关。
- **文本先验对照**：`prior(label) = 该标签对其余 334 张图的平均余弦`（留一），
  `corrected = sim − prior`。若 corrected 仍≈50%，说明原始胜负来自“某些标签文本
  天生更贴这类图”，不是图像身份证据。
- 鲁棒性下限：`--min-pairs` 固定为 30；本次 335 对，未触发 “insufficient data”。

## 4. 结果

### 4.1 主指标（N=335，93 标签）

| 指标 | 值 | 备注 |
|---|---:|---|
| 3 选 1 top-1（true） | **11.0%** [8.1, 14.9] | 随机基线 33.3% |
| true vs random 二选一 | **51.9%** [46.6, 57.2] | 随机基线 50% |
| true vs 同类目 random | 52.0%（n=331） | 同类目内同样无线索 |
| 先验校正后 二选一 | **52.5%** [47.2, 57.8] | 扣掉文本偏置仍≈随机 |
| 先验校正后 3 选 1 | 26.6% | 仍低于 33.3% |
| 每型号 1 张（n=93） | 9.7% / 48.4% / 46.2%* | 3 选 1 / 二选一 / 校正后 |
| truck 夺魁率 | **77.0%** | 258/335 |
| top-1 分布 | true 37 / random 40 / truck 258 | 真模型输给随机型号 40 次 |
| 平均余弦 | true .2764 / random .2748 / truck .3030 | 真标签没有更高 |

\* 每型号 1 张：3 选 1 9.7%，二选一 48.4%，先验校正 46.2%。

### 4.2 margin 分布

| margin | 中位 | p10 | p90 | min / max |
|---|---:|---:|---:|---:|
| top-1（true − 最强对照） | **−0.0307** | −0.0634 | +0.0018 | −0.0963 / +0.0478 |
| 二选一（true − random） | +0.0012 | −0.0232 | +0.0251 | −0.0591 / +0.0645 |
| 先验校正后二选一 | +0.0009 | −0.0144 | +0.0140 | −0.0393 / +0.0535 |

90% 的图 top-1 margin 为负（仅 11% 为正）；90 分位才 +0.0018，最大也只有 +0.0478。
二选一 margin 中位 +0.0012，和“同分布噪声”没有区别。

### 4.3 子集（先验校正后的二选一）

| 子集 | n | 原始 | 校正后 |
|---|---:|---:|---:|
| single_vehicle（整车） | 158 | 50.0% | 51.9% |
| part（部件特写） | 173 | 53.8% | 52.0% |
| multi_vehicle | 4 | 50.0% | 100%（n 太小） |
| 标签纯拉丁（C90/LSS320B/…） | 52 | **63.5%** | **46.2%** |
| 标签含中文 | 283 | 49.8% | 53.7% |
| exact tier | 98 | **38.8%** | 48.0% |
| accepted_any | 170 | 50.6% | 55.9% |
| 未 accepted | 165 | 53.3% | 49.1% |

两个要点：

1. **纯拉丁标签的 63.5% 是假信号**：扣掉文本先验后掉到 46.2%。例如
   “Zetros 4051 AS 6×6” 原始 0.3122 > random 0.2850，但它的先验 0.2970 本身就高，
   校正后 0.0152 < random 0.0204。看起来“认得型号”，实际是标签文本对这类图的
   平均亲和度。
2. **exact tier 反而低于随机**（38.8%）：短代码标签（“临工重机 CMT66A”）
   竞争不过带“扫路车/救险车”等类目词的长描述标签（0.2333 vs 0.2511）。
   这是语义/词频效应，不是图像识别。

|---|---|---|---:|---:|---:|---:|
| `f8cd33e793c5` 江铃 PFT5042TQZP6C 清障车 | single | .2756 | .3099 | .3719 | −0.0963 |
| `6c49ecd4c121` 陕汽德御Q200 一拖二清障车 | single | .2700 | .3292 | .3583 | −0.0882 |

共同点：真标签没有带来任何“这张图专属”的加分；truck 因为泛化语义几乎总是最高。
连“整车可见”的 single_vehicle 子集也是精确的 50.0%（79/158），说明问题不在部件图，
而在这套文本标签 + 英文 CLIP 根本没有型号级视觉分辨力。

## 6. 限制

- **标签噪声（最大）**：`asset_meta.model` 是检索查询目标，不是人工真值；图可能是
  错型号、错品牌、经销商场地多车、甚至无关图。任何“准确率”都是相对这个噪声标签的上限。
- **英文模型 + 中文语境**：UForm3 是 english-small；中文型号主要靠品牌/字母数字片段，
  中文语义基本丢失。纯拉丁子集也不能证明有效（见先验校正）。
- **候选语义偏置**：random 标签的长度/类目词会改变文本先验；已用留一先验校正，
  但无法完全消除。truck 作为泛化对照天然占优，3 选 1 的 11% 不能单独当作“模型很差”的
  全部证据——二选一 51.9% 才是“没有身份信号”的主证据。
- **语料有限**：只有 m43 的 5 类车（沙漠牵引/叉车/压路机/清障/扫路），93 个标签、
  每型号约 6 张，图片是 503–1200px 网络图；结论不外推到别的品类/数据源。
- **统计口径**：335 条按 asset 计，同型号 6 张相关；已用“每型号 1 张”（n=93）复核，
  结论不变（48.4%）。二选一 CI 用 Wilson，未做聚类稳健标准误。
- **验收代理**：`accepted_any` 是 part 级验证任意通过，`accepted_model` 是字符串匹配
  `accepted_targets`，都不是“整图身份正确”的真值。
- **只测文本候选**：没有测 image-to-image 参考图匹配（见建议），不能据此否定
  “视觉参考图”路线。

## 7. Go / No-Go

**No-Go：不要把 CLIP 文本标签身份接进 VERIFY。**

理由：二选一 51.9%（CI 含 50）、先验校正 52.5%、去相关子集 48.4%、margin 中位≈0、
truck 夺魁 77%。接线只会增加每图约 20–30ms CPU 和一次新阈值校准，却没有任何可用的
区分度；若拿 `top-1 == true` 当门槛，会否掉 89% 的图（而“truck 分最高”并不代表图错）。

**保留现状**：CLIP 继续只做 `gate.check()` 的 keep/drop 与场景/视角提示，不承担身份。

**如果还要继续**（另立任务，不在 S2-01 范围）：
1. 用**参考图到参考图**（image embedding 最近邻）而不是文本标签：每个型号先积累
   多视角已验收图，再测 top-1 与 margin；这可能比文本强，但需要先解决“参考集本身
   是否干净”。
2. 型号铭牌/贴纸 OCR（视觉文字）比 CLIP 更对症，但要处理模糊/角度。
3. 若未来上 VLM（联网/成本），必须单独评估并与文本证据做融合，不得默认生效。
