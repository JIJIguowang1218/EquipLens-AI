## 2. 每个模块的边界

### M3 素材获取（最重）

| 子能力 | 做 | 不做 |
|---|---|---|
| 自动检索 | 按车型名检索整车图，门卫过滤 | 不做全网爬虫，受 robots/配额约束 |
| 上传分流 | VLM 三分类（整车/部件/其他） | 不做自动抠图 |
| 归组识别 | 嵌入聚类 + VLM 判型号，人确认 | 不追求全自动，允许人工兜底 |
| 缺图处理 | 标红"缺整车图"，阻断该车 | 不用相似车型顶替 |

### M4 分析

- 一次调用产出一台车的全部部件（图多时按部件补证）
- 失败重试 1 次，仍失败标 `needs_review`，不阻断整批
- **不做**：跨车对比结论、趋势判断

### M5 版式

- 一车一页 16:9；左主图+前脸文本；右区图/文/图/文四行
- 图按框裁切显示（源框不变）
- **不做**：多套模板、自动配色

### M6 导出

- PPTX：全部元素可编辑（图片/文本框/形状）
- PDF：只读交付版
- **不做**：PPT 母版管理、动画

## 3. MVP 边界（这次要交付的）

**做**：
1. 五步流程能跑通（3 台车）
2. 自动生成 → 人工可改（裁框/文字/版式）→ 导出 PPTX
3. 单机部署（`start.bat` 起服务 + 开浏览器）
4. 全程可回退、失败可重试

**不做（写进 README 的"规划中"）**：
- 用户系统 / 多项目 / 团队协作
- 跨车对比页、情绪版、品牌基因页
- 自训 VLM、本地大模型
- 移动端

## 4. 非功能要求

| 项 | 目标 |
|---|---|
| 单次成本 | < ¥5（10 台车分析 + 识别） |
| 单台耗时 | 分析 20–40s；整批 3 台 < 3 分钟 |
| 部署 | 单机 4C8G 可跑；不依赖 GPU |
| 合规 | 遵守 robots；抓取频率限制；密钥只在服务端 |
| 可复现 | 同一输入 + 同一模型版本 → 同一输出（除模型随机性） |

## 5. 技术封装（初稿）

```
浏览器（React 19 + TS，Vite 构建；见 docs/web-interaction-spec-v2.md §11）
   │  HTTP / SSE
FastAPI（单进程）
   ├─ 任务队列（线程池，串行跑分析，避免并发打爆 API）
   ├─ 任务落盘（runs/<id>/state.json，可断点）
   └─ 调用现有 Python 模块（M1–M7，不重写）
静态资源：页面产物（HTML/PPTX/图片）由 /files/<run_id>/ 提供
```

- **前端**：React 19 + TypeScript + Vite（2026-11-03 改定；原"单页 + 原生 JS"作废，理由见 `docs/web-interaction-spec-v2.md` §11）
- **分析串行**：一次一台车，进度可推
- **失败隔离**：单台失败不影响整批

## 7. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| API 超时/限流 | 分析中断 | 重试 + 串行 + 失败隔离 |
| 抓图被拦 | 素材缺失 | 门卫 + 降级 + 允许上传 |
| 打包体积大（torch） | 便携包 500MB+ | 网页版只装 onnx，torch 留离线 |
| 评委网络差 | 页面卡 | 静态资源本地化，无 CDN 依赖 |
