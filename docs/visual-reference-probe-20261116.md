# S2-06 可行性探针：image-to-image 每型号参考图库（2026-11-16）

**结论（先看这里）**

- **研究问题：是。** image-to-image 每型号参考图库明显比零样本文本标签更能区分
  型号身份：留一 top-1 **53.0%**（35/66）vs 机会 **6.7%**（15 个候选型号），
  **8.0×**，二项检验 p=5.5e-24。S2-01 的文本标签是 11.0% vs 33.3%
  （**0.33×**，等于没有信号）。在 S2-01/S2-06 这两条视觉身份路线里，这是第一次
  看到明显超过随机的信号。
- **工程结论：NO-GO（暂不接 VERIFY）。** 绝对准确率、margin 和稳定性都不够：
  4/15 型号 0 命中；扫路车家族 30% vs 机会 33.3%；top-1 margin 中位仅 **+0.003**
  （正确样本 +0.026）；31 个错误里 8 个被同一个 hub 质心吸走；29% 的错误跨车型
  家族；66 张测试图里 37 张在同型号内存在“同标题”参考图，去相关后 51.7%
  （n=29），与主结果基本持平，但样本骤减且仍是同 run。这些证据说明它现在更像
  “粗粒度外观/场景相似”，不足以当身份证据门槛。
- **下一步：conditional-go（离线建库，不接生产）。** 翻转条件见 §7。

## 1. 问题

S2-01 已经证明：把型号名写成文本标签（`a photo of a {model}`）喂给同一套 UForm3，
在 335 张图上 3 选 1 top-1 只有 11.0%（随机 33.3%），二选一 51.9%（等于抛硬币），
扣掉文本先验后仍无信号。**文本标签路线关闭。**

本探针只回答下一个问题：

> 如果先给每个型号攒一组参考图，用**图像嵌入的每型号均值（prototype）**做最近邻，
> 能不能把型号分开？分开得比文本好多少？

这里不训练、不微调、不换模型，只测“现成 UForm3 图像嵌入 + 参考图库”这一条路。

## 2. 数据与标签

| 项 | 值 |
|---|---:|
| 扫描 | `data-test/runs/m43-*/state.json`，10 个 run（base + sess） |
| 去重后 image + 非空 `model`（按 asset_id，base 优先） | 335 |
| verification identity 分布（资产级） | confirmed 92 / probable 80 / unknown 163 |
| **主口径：identity == confirmed** | **92 对 / 35 个型号** |
| 其中图片数 ≥3 的型号 | **15** |
| 主口径最终图片 = 留一测试数 | **66 / 66**（每张图各当一次测试） |
| 因只有 2 张图被排除的型号 | 6 个（见 JSON `two_image_models`） |
| 车型家族图片数 | roller 29 / desert 18 / sweeper 10 / wrecker 5 / forklift 4 |
| 精确字节重复（md5） | 0 组 |
| 同型号内 dHash 近重复（Hamming ≤8）测试图 | 4 / 66 |

**标签来源与口径。** `confirmed` 不是人工真值，而是 `src/equiplens/retrieval_engine/web.py`
的规则核验结果（第 136–151 行）：标题里出现完整型号名、或型号编码命中，即
`identity="confirmed"`；品牌/车系/构型弱命中是 `probable`；其余 `unknown`。
所以它比 “检索查询目标” 干净，但仍是**文本规则标签**：图可能不是该型号、可能是
同底盘不同上装、也可能是经销商多车图。`accepted`（confirmed + probable，172 对）
留作敏感性口径，主结果不混入。

**跨 run 去重口径。** 同一 asset 可能在 base/sess 都以**同字节**出现，而 identity
规则对标题标点敏感（例如 base 标题缺型号串、sess 标题有）。主口径取两处更强的
证据：2 张 base 标题未命中、sess 标题命中的图按 `confirmed` 计入，所以 confirmed
是 92 对而不是 base-first 的 90 对；两处都不命中的仍排除。这样既保留 base 优先
的图片路径，也不把已确认的图误降级。

**相关性问题（重要）。** 15 个合格型号的图全部来自单一 run（base 或 sess），
参考图和测试图同 run、同搜索来源。66 张图只有 43 个唯一页面标题；37 张测试图在
同型号内至少有一张**标题完全相同**的参考图，2 个型号（EQ245、MOL H6066）全部图
共用一个标题。换句话说，一部分“识别正确”可能是**同一网页/同一台车**的检索，
不是跨车、跨场景的型号识别。§4.5 用同标题剔除做了敏感性。

## 3. 方法

- **图像编码**：`src/equiplens/gate.py` 的 UForm3 image encoder（ONNX CPU，256 维），
  单位向量、余弦相似度；与门卫同一权重、同一预处理，不新增模型。
- **参考库**：每型号取图片嵌入均值，L2 归一化作为质心。
- **留一法（LOO）**：测试图 i 的**真型号质心用该型号其余 N−1 张图重算**；其它型号
  质心用其全部图。相似度 top-1 在全部 15 个候选型号里选。N≥3 保证每张测试图至少
  有 2 张参考图。
- **机会基线**：`1 / num_models = 1/15 = 6.7%`（任务指定口径）。另报
  majority-class baseline（9.1%）和 balanced accuracy（每型号召回的平均）。
- **margin**：`cos(test, 真型号 LOO 质心) − max cos(test, 其它型号质心)`；
  同时报每型号质心到最近邻质心的间隔（`1 − cosine`）。
- **家族内 top-1**：候选只保留同 family（desert/forklift/roller/wrecker/sweeper），
  测“同品类选型”这个更难也更真实的子任务。
- **近重复控制**：dHash 64bit，同型号参考图 Hamming ≤8 视为近重复；另用
  “同型号内 title 完全相同”做来源相关代理（不是严格同车判定）。
- **稳健性**：对 `accepted` 口径（confirmed + probable；172 对里有 33 个型号、
  140 图过 ≥3 门槛）重跑同一套留一评估。
- **不跑文本基线**：文本已在 S2-01 同语料测过；本轮按 S2-06 范围跳过。两轮候选
  数不同（3 vs 15），**只比较相对机会的倍数（lift），不直接比较 raw 准确率**。
- **数据不足保护**：合格型号 <10 或留一测试 <30 时，写
  `status="insufficient_data"` 并以退出码 2 停止。本次 15 型号 / 66 测试，
  未触发。

### 4.5 稳健性

| 检查 | n | top-1 | 机会 | lift |
|---|---:|---:|---:|---:|
| 主结果（confirmed） | 66 | 53.0% | 6.7% | 8.0× |
| 剔除 dHash 近重复参考的测试图 | 62 | 51.6% | 6.7% | 7.7× |
| 剔除“同型号有同标题参考”的测试图 | 29 | **51.7%** | 6.7% | 7.7× |
| accepted 口径（confirmed + probable，33 型号） | 140 | **42.1%** | 3.0% | **13.9×** |

- 近重复不是主因：dHash 只标出 4 张，剔除后从 53.0% 到 51.6%（−1.4pp）。
- **同标题剔除后基本持平**（53.0% → 51.7%，n 从 66 降到 29）：这批数据里
  “同网页/同车”不是准确率的主要来源；但同标题标记只覆盖 37/66，且所有参考图仍
  同 run，**run-disjoint 泛化仍未验证**。
- 放宽到 accepted、候选从 15 增到 33，raw top-1 降到 42.1%，但机会降到 3.0%，
  lift 升到 13.9×（p=3.7e-51）。**信号在更大、更噪的标签集上仍然成立**；
  也提示候选型号越多 raw 准确率越低，生产 90+ 候选不能外推 53.0%。

31 条全部明细在 JSON `failures`。错误结构：

- **同一质心当 hub**：`东风小多利卡扫路车国VI` 自己 0/3，却吸走 **8 条**别型号的

## 5. 哪些型号行、哪些不行

**行（≥75% 或家族内明显超机会）**

- desert 6x6 四款：家族内 83.3%（15/18），全局 77.8%；EQ245、SHACMAN 满分。
  外形、颜色、军/民风格差异大，参考图均值能站住。**但 MOL H6066 只有 2/5（40%）**，
  说明“同家族整体好”不等于每个型号都稳。
- 陕汽德御 Q200 清障车：5/5。平板清障车轮廓独特，且 5 张图来自 2 个标题，
  不是纯同图重复。
- CLW5040 扫路车：3/4，但平均 margin 为负（−0.005），属于“险胜”，不稳。
- YZ18JC 压路机：4/6（67%），roller 家族里最好。

**不行（0%）**

- **CPD25 叉车**：4/4 全错，预测成分散到扫路车/压路机。绿色叉车外形本应好认，
  失败更像“背景/场景主导 + 只有 4 张参考”的均值偏移，而不是“车型不常见”。
- **26H 压路机**：0/3，且 margin 最差（−0.089）；3 张图里 2 张被判成 LSS320B。
- **东风大多利卡 / 东风小多利卡扫路车**：各 0/3；都被对方或 CLW 吸走，扫路车
  家族整体等于机会（30% vs 33.3%）。
- **LSS 系列 / YZ7G**：33–60%（YZ7G 33%、LSS320B 40%、LSS2101-2 50%、
  LSS1001 60%），在 6 个相似压路机里能排对一部分，但平均 margin 为负，
  不能当稳定信号。

一句话：**参考图库对“外形差异大、单车/单网页”的型号有效；对“同底盘不同上装、
白色轻卡、相似压路机”无效。** top-3 77.3% 说明真型号通常还在附近，但 top-1
不足以直接判身份。

## 6. 限制

- **标签噪声（最大）**：`confirmed` 是“标题/型号码命中”规则，不是人工核对；
  图可能是错型号、同底盘不同上装、经销商多车图。所有准确率都是相对这个噪声标签，
  不是相对人类真值。
- **来源相关 / 非 run-disjoint**：15 个型号的参考图与测试图全部同 run；66 张图
  只有 43 个唯一标题，37 张测试图有同标题参考图，2 个型号全部图共用一个标题。
  剔除同标题后 51.7%（n=29），与主结果 53.0% 基本持平；但这不是“泛化没问题”的
  证据——只是同标题标记覆盖不到一半，且所有参考图仍同 run。跨 run、跨车、跨场景
  的泛化仍未验证。
- **样本小且极不稳定**：15 个型号、66 张测试、每型号 3–6 张参考。单型号准确率的
  Wilson CI 很宽（3/3 的 95% CI 下限也只有 0.44），不要把 100% / 0% 当稳定结论。
  一个直接例子：给 SHACMAN/Mol HF 各补 1 张跨 run 同字节的 confirmed 图
  （64→66 张）后，竞争质心变化使 MOL H6066 从 4/5 掉到 2/5，top-1 从 54.7%
  掉到 53.0%——3–5 张参考的质心对竞争型号的微小变化非常敏感。
- **候选集小**：15 个候选，机会 6.7%；m43 语料实际有 93 个型号标签。accepted 口径
  33 个候选时 raw top-1 已降到 42.1%，生产候选更多只会更低。
- **margin 极小**：全样本中位 +0.003，正确样本 +0.026；质心间最近邻间隔 0.045，
  同型号内散度约 0.067。阈值校准会很脆弱，容易“差一点就翻”。
- **编码器能力**：UForm3 english-small 是通用图文模型，256 维；没有背景抑制、
  没有部件/视角建模。hub 现象说明它抓到了“户外白车/路面”这种粗粒度场景。
- **只覆盖 5 类车**：沙漠牵引/叉车/压路机/清障/扫路；网络图 500–1200px。
  不能外推到其它品类、其它数据源、真实用户拍摄。
- **比较口径**：文本基线（S2-01）是 3 选 1，本轮是 15 选 1，raw 准确率不可直接
  比；本文用“相对机会的 lift”比较（0.33× vs 8.0×）。
- **未测融合**：没有把视觉相似度和文本/规则证据做融合，也没有做阈值/校准。

## 7. Go / No-Go

**NO-GO：本轮不要把 image-to-image 参考图库接进 VERIFY。**

理由（按重要性）：

1. **绝对准确率不够**：15 候选 top-1 53.0%、balanced 49.7%；如果当身份门槛，
   近一半会判错，且 4/15 型号全错。
2. **margin 太小且结果不稳**：正确样本中位 +0.026，和同型号内散度同量级；
   给同家族另两个型号各补 1 张图，就能让 MOL H6066 从 4/5 掉到 2/5、整体 top-1
   从 54.7% 掉到 53.0%。阈值无法稳定校准，接入后会出现“同一张图换个压缩就翻判”。
3. **失败是结构性的，不是样本偶然**：扫路车家族 30% vs 33.3% 机会；hub 一个质心
   吸走 8/31 错误；29% 错误跨家族。这些不会靠多跑几次消失。
4. **来源相关未解决**：同 run、37/66 有同标题参考；剔除同标题后 51.7%，只降
   1.3pp，但同标题标记覆盖不到一半，且仍没有 run-disjoint、跨车、跨场景验证。
5. **候选规模差距大**：生产 90+ 型号，本轮 15 个；33 候选的 accepted 口径已降到
   42.1%。

**但研究结论是正向的，不要误读成“视觉没用”：**

- 文本标签 0.33× 机会 ≈ 没有信号；image-to-image 8.0×（33 候选时 13.9×）。
- 这是目前唯一明显超过随机的视觉身份信号，说明“攒参考图 + 图像最近邻”方向对，
  只是**数据量、标注质量和编码器分辨率**还没到生产可用。

**什么情况下改判 GO（建议另立任务）：**

1. **数据**：≥30 个型号、每型号 ≥10 张、≥300 张测试图；至少一部分人工确认；
   参考图与测试图 **run-disjoint**（不同批次/不同来源/不同车）。
2. **指标门槛**：top-1 ≥75%、balanced ≥70%、去同标题/去近重复后 top-1 ≥70%、
   margin p10 > 0；且单型号不能有“0 命中”的结构性黑洞。
3. **方法**：hubness 校正（CSLS / 去全局均值）、背景/涂装抑制、按视角分质心、
   margin 校准；必要时换更强编码器或轻量微调。
4. **产品形态**：在达标前最多做 **top-k 候选 shortlist**（本轮 top-3 77.3% vs 20%），
   绝不能做 accept/reject 的硬门槛。

如果产品现在就要一个“能用”的形态：把参考图库当**人工复核的候选排序**，
不是 VERIFY 的身份证据。等 §7 的 1–3 满足后再评估接线。
