# Router 兜底与意图框架设计（2026-11-16）

> 背景：100 条合成 holdout 经产品负责人审核，13 条不合理/罕见、6 条能力外、10 余处口径修正。
> 结论：**当前框架缺“能力、阶段、数量语义”三层**，导致越界请求被硬映射、跨阶段误读、数量动作混淆。
> 本文只定设计与兜底策略，不改代码；对应 BC-S4-006/007/008/009、BL-017。

## 1. 系统性缺陷（不是个别标注问题）

1. **只有动作分类，没有能力判定**：router 把“去水印/印刷级/天气筛选/写周报”映射到最近的
   `quality`/`report`，用户以为能做、系统其实做不到。
2. **没有阶段维度**：同一句话在“输入中 / 运行中 / 看到结果后”含义不同；
   “第 N 张换掉”在交付前无资产可指，当前只在 pending/confirm 层处理，不在意图层。
3. **数量语义混在一起**：总量、每款张数、同一台车加图、条件扩张（每款补到 N）被塞进
   `plan.quantity` / `fill.quota` 两个动作。
4. **复合意图不拆**：“排除平顶 + 只看高顶 + 补总数”只出一个 target。
5. **澄清太笼统**：“你想改哪一部分？”不是可选项，用户难以回答。
6. **没有“不做”这个动作**：系统不会说“这个我做不到”，只会硬猜。

## 2. 目标：把损失按“代价”排序

| 行为 | 代价 | 策略 |
|---|---|---|
| 破坏性误操作（删错/换错） | 最高 | 永不默认；必须确认或可撤销 |
| 越界请求被假装能做 | 高 | 能力层直接说“不支持”，给替代 |
| 漏做（该改没改） | 中 | 不确定时先问，不猜 |
| 多余澄清 | 低 | 控制在必要范围，给默认项 |

原则：**宁可多问一句，不可错删一张；宁可说做不到，不可假装能做。**

## 3. 框架：四层判定

```
输入 + 阶段 + 会话上下文
  → ① 能力判定（supported / partial / unsupported / out_of_domain）
  → ② 阶段判定（pre_run / running / delivered）
  → ③ 语义判定（动作 + 数量语义 + 目标 + 复合拆分）
  → ④ 置信/歧义判定
  → 响应：apply / confirm / clarify(选项) / unsupported(说明+替代) / out_of_scope
```

- **能力层**用能力标志（如 `can_remove_watermark=false`、`can_export_print=false`），
  不建领域实体表；能力来自产品配置。
- **阶段层**限制可用动作：`pre_run` 不允许 `delivered.*`/`verify.blacklist`；
  `delivered` 才允许资产级替换/删除；`running` 允许加条件/数量/排除。
- **语义层**输出最多 3 个动作，带顺序与依赖（先排除、再补数量）。
- **置信层**：`confidence<0.65` 或目标缺失/多义 → 澄清，不执行破坏性动作。

## 4. 数量四义（必须拆开）

| 语义 | 例子 | 动作 |
|---|---|---|
| 总量 | “总共 20 张 / 数量改 12” | `plan.quantity`（总量） |
| 每款张数 | “每个车型统一 6 张 / 从 4 调到 6” | `plan.quantity_per_model`（新增；条件扩张） |
| 同车补图 | “这台豪沃再多来几张” | `fill.quota`（**仅限同一台车已存在**） |
| 条件补到 N | “不够 6 张的补到 6 张” | `plan.quantity_per_model` + 补池 |

规则：**出现显式总数/每款数 → 改总量/每款，不进 `fill.quota`**；`fill.quota` 只在
“同一台车要更多图”时触发（用户 2026-11-16 口径）。

## 5. 兜底动作矩阵

| 情况 | 动作 | 用户看到什么 |
|---|---|---|
| 支持 + 明确 + 非破坏 | 直接应用 | “已改：…（下一轮生效）” |
| 支持 + 明确 + 破坏 | 确认后应用 | “将删除/替换第 N 张，确认？”+ 可撤销 |
| 支持 + 目标不明 | 澄清（2–3 个选项） | “你指哪张？①第 2 张 ②第 3 张 ③都不对” |
| 支持 + 数量不明 | 澄清（给默认值） | “补几张？默认 2 张，也可输入数字” |
| 部分支持 | 说明 + 替代方案 | “去水印做不到；可换一张无水印来源的图” |
| 不支持 | 明确拒绝 + 可做什么 | “印刷级导出暂不支持；可导出原图/高清图” |
| 越界/无关 | 说明范围 | “我只做工程车图检索与交付，不写周报” |

**绝不**：把不支持映射成最近动作；把不明确的目标默认成第 1 张；把越界请求静默忽略。

## 6. 澄清的写法（降不满）

- 给 **2–3 个具体选项**，不要开放问“你想改哪部分”；
- 给**默认项**（如“不操作/保持原样”）；
- 允许用户直接说“就第 2 张”而不必选编号；
- 一次只问一个维度（目标、数量、范围），不要一次问三个。

## 7. 指标（替代单一总分）

- 分阶段准确率（pre_run / running / delivered）；
- **破坏性误操作率 = 0**；
- 能力外识别率（该说“做不到”的有没有说）；
- 澄清命中率（问完后用户是否给出有效补充）；
- 用户纠正率（下一轮是否推翻上一轮）；
- 不必要澄清率（本可直接做的却问了）。

## 8. 落地顺序

1. **P0**：classify 增加 `stage` 与 `feasibility` 字段；unsupported/out_of_scope 响应；不改动作表。
2. **P1**：数量四义拆分；`fill.quota` 限定同车。
3. **P2**：复合意图拆分（≤3）+ 选项化澄清。
4. **P3**：按 BL-016 建分阶段真实高频测试集，按新指标验收。
