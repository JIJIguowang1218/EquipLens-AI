# 优化轮次 5：结构化槽位 + 冻结评估协议（2026-11-14）

## F2 结构化槽位（slots）

**目的**：把“品牌/车系/型号码/构型”从一句自由文本里拆出来，减少字符串猜测；
同时让 `search_key` 可以由槽位确定性派生，而不是每次靠模型自由写。

**方法**：
- 抽取 prompt 增加 `slots{brand, series, model_code, config}`，并保留 `search_key`；
- `validate_extraction` 解析槽位；`search_key` 缺失时用 `derive_search_key(slots, model)` 派生
  （型号码 > 车系 > 品牌，再拼构型）；
- `merge_candidates` 合并时补齐缺失槽位；
- 5 份冻结 brief 重跑（`data-test/runs/p5-slots-20261114/`），与 p3（只有 search_key）对照。

**结果**：

| 指标 | 数值 |
|---|---:|
| 槽位覆盖（有 code 或 series） | **137/145（94.5%）** |
| 车型含型号码 → 槽位给出码 | **56/56（100%）** |
| 其中与车型名一致 | **55/56（98.2%）**（唯一不匹配是 `TBH 280` vs `TBH280`，空格归一差异） |
| 车型含构型 → 槽位一致 | **26/26（100%）** |
| 有码车型的 `search_key` 含码 | **55/56（98.2%）** |
| 候选数（p3→p5，5 case） | 142 → 145（+3/-2/0/0/+2，噪声内） |

**结论**：**好，采纳**。槽位把“品牌/车系/码”变成可校验字段，派生 key 的码覆盖 98%，
且不改变候选数量级；`code_share` 略降 3–12 个百分点（同一批搜索下抽取风格差异），在噪声范围内。

**冲突**：
- 与“不要表”无冲突：槽位由模型从**来源文本**读出来，不是词表；
- 与旧 plan 兼容：没有 `slots` 的 plan 仍走 `normalize_query`，`search_key` 为空即跳过末档。

## F6 最小评估协议（冻结快照 + 指标 + 配对 bootstrap）

**目的**：让“这次改动是变好还是变坏”有可归因的口径，而不是看单次数字。

**方法**（`scripts/eval_plan_snapshot.py`）：
1. `--freeze <dir>`：把一组 plan 冻结成 `SNAPSHOT.json`（每个 case：候选数、code/generic 占比、
   search_key/槽位覆盖、pool_ok、query 列表、plan sha）；
2. `--compare A B`：逐 case 计算差值，并对每个指标按 case 做 **2000 次配对 bootstrap**，输出 95% CI；
3. 指标只选**可离线计算**的（不含“相关性”这类需要人工的）；
4. 判定规则（建议写死）：CI 跨 0 → 无结论；CI 全正/全负 → 有方向。

**结果**（p3 vs p5）：

| 指标 | 均值差 | 95% CI | 判定 |
|---|---:|---|---|
| 候选数 | +0.6 | 宽（含 0） | 无结论 |
| code 占比 | -0.064 | 含 0 | 无结论 |
| generic 占比 | +0.076 | 含 0 | 无结论 |
| search_key 覆盖 | 0 | — | 无变化 |
| **槽位覆盖** | **+0.938** | **[0.874, 0.993]** | **显著（符合预期）** |

**结论**：协议能工作，但有两个必须写明的局限：
- 只有 **5 个 case**，bootstrap 区间很宽，只能检测“像槽位覆盖这种接近 100% 的变化”；
- 候选数受**每次搜索返回结果波动**影响（同 brief 历史 9–27），单次 A/B 不能归因到 prompt 改动。

因此 F6 目前是“**可复现的最小骨架**”，还不是“能判定召回优劣的评估集”——后者需要
**冻结 query 集 + 固定池深度 + 人工/LLM 相关性标注**。

## 本轮结论

- F2 槽位：**好，采纳**（覆盖 94.5%，码/构型一致率 98–100%）；
- F6 协议：**骨架可用**（可冻结/可比较/有 CI），但样本量不足，需扩到 ≥3 次重复 + 8–10 个 brief；
- 未做：F4（Fellegi–Sunter 去重，需要槽位字段稳定后再上）、F5（RRF，依赖 F6 评估集）。
