# 页数模型与页槽判据

## 报告结构（约 20 页）

| 页类 | 页数 | 内容 |
|---|---:|---|
| 封面 / 封底 | 1 + 1 | — |
| 方法与来源 / 目录 | 1 | — |
| 情绪版 | 1~2 | 待定 |
| **整车页** | **10~14** | 一车一页：1~2 张主图 + 3~4 个部件裁图 + 分析文本框 |
| **部件专项页** | **0~2** | 一部件一页：图上+文本框为一个单元，可排 5~6 个 |
| 合计 | ≤20 | 硬校验：`fixed_pages + vehicle_slots + part_page_slots ≤ total` |

## 判据

**合格主图**（整车页的成立前提）：

| 项 | 要求 | 谁判 |
|---|---|---|
| 主体 | 单台车、完整、无遮挡 | `gate.py`（现成） |
| 分辨率 | 长边 ≥ 1200px | 图片元数据 |
| 视角 | hero_45 / side（可含 front） | `probe.py` 标签 |
| 可裁 | 能支撑请求部件裁图 | `part_views` 粗判 + VLM 后置 |

**整车页合格**：≥1 张合格主图 + 1 张备用；请求部件中 ≥3 个可裁（请求 ≤3 个时要求全覆盖）。

**部件专项页合格**：该部件在 ≥5 台车的主图上可裁（对应一页 5~6 个单元）。

## 停止条件（省预算的关键）

- 单目标：**拿到 1 张合格主图 + 1 张备用即停**，不追求多视角；
- 全网：**凑够 `vehicle_slots` 个页槽即停**，不必跑完整个名录；
- 凑不满：输出缺口报告（哪几槽空、是"没车"还是"主图不合格"），**不许降标准凑数**。

## 缓冲

`extra = max(2, ceil(0.15 × N))`；薄类目（可用车型明显少于 N）提到 25%。

- 备选**不占页槽**，只在推荐集判废时按优先级顶上；
- 备选也爬图（便宜），但**不跑文本**（文本不是门槛，转正后再补）；
- 转正必须落账（写 `decisions`）。

## 为什么文本不是门槛

一车一页里的部件分析文字可由分析模块生成，网上专业设计分析稀少是常态。文本只作定调/语汇/事实加分，**不参与页槽是否成立的判断**，也不触发"放闸"。
