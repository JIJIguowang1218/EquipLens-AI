# Router 100 条 holdout：产品负责人审核记录（2026-11-16）

> 结论先行：**这是广度集，不是真实频率集**。不得把 81–82% 当线上准确率，也不得当作
> “真实用户输入”写进验收。真实场景主要在**半路补条件、改数量、提新要求、看到图后替换/增加**，
> 且**输入阶段 / 过程中 / 看到结果后**各自有不同话术。

## 1. 判定为“不合理 / 罕见 / 不符合产品任务”的条目

`1, 7, 11, 16, 20, 22, 34, 46, 50, 51, 57, 70, 90`

理由类型：
- 不像一般用户会说的话 / 逻辑不自洽（如 `嗯，我再想想`、`这个颜色挺有意思的`）；
- 不属于本产品任务（如 `帮我写个周报吧`）；
- 跨阶段硬造（输入阶段问“第4张换高清”，此时还没有图）；
- 真实出现频率极低（如单独说“排板改成横版16:9”）。

这些条目**保留在广度集**，但**不计入真实分布指标**。

## 3. 测试设计结论

1. 本 100 条只适合测**广度**（能不能想到某类说法），**不能反映高频业务指标**；
2. 真实高频集中在三个阶段：
   - **输入阶段**：漏条件、补构型、改数量、加品牌；
   - **运行中**：改数量、加排除、补要求；
   - **看到结果后**：换第 N 张、删图、增加同款图、画质抱怨。
3. 下一版测试必须**按阶段分层、按真实频率加权**，并优先使用真实日志/客服话术；
4. 指标改为：**分阶段准确率、破坏性误操作率（目标 0）、能力外识别率、澄清命中率**，
   不再用单一总分。
