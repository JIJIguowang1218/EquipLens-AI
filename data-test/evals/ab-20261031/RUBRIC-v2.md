# A/B 评分细则 v2（预注册，2026-10-31）

取代 `RUBRIC.md`。v1 的漏洞：只测判断质量、不测交付性，导致"分更高但交不出报告"。

## 主指标（门槛，不是加权分）

| 指标 | 通过线 | 说明 |
|---|---|---|
| `fill_rate` = 已占整车槽 / 12 | **≥ 0.85** | 交不出 10 页就没有产品价值（A 基线 0.927） |
| `hard_errors` | **= 0** | 见下定义 |
| `schema_pass` | **8/8** | `check_list.py` 返回 ok |

**任一项不达标即判"skill 不可交付"**，不看六维分数。

## 硬错误定义（出现即 0 容忍）

1. 未验证的具体型号名占槽（编造风险）；
2. 阻断式确认（scope=all）生效时仍有目标占槽；
3. 备选占槽、槽位重复、页数超限（`check_list` 会拦）；
4. 结构上不存在的组合被放进推荐位（如履带吊占"支腿"槽）；
5. 编造图库数字（库为空却写"已有 N 张主图"）。

## 质量门槛（六维，各案例 ≥5/6 才计合格）

沿用 `RUBRIC.md` 的 D1–D6：口径构型、结构事实、部件轴、理由可审、必要确认、诚实度。

- **合格线**：8 例中 ≥7 例达到 5/6，且无一例 <4/6；
- 六维作为"质量闸门"，不参与主指标排序（避免再次出现"高分低交付"）。

## provisional 的正确用法（评分时特别看）

- 方向级目标（无具体型号）**可以**占槽，但必须 `verify_by` + `decisions` 记录转正动作；
- 每个 provisional 都要能被一句话说清"下一步拿什么动作把它变成 recommended"；
- 若把**所有**槽都标成 provisional 而不做任何取舍（例如 12 槽全是"待验证方向"），视为**规避判断**，D1/D5 各扣 1 分。

## 判定方法

1. 先算 `fill_rate` / `hard_errors` / `schema_pass`；
2. 不过线 → 直接结论"不可交付"，不看六维；
3. 过线 → 再看六维合格数与 A 基线的对比（A 的 89/96 与硬错误 1 固定不变，不重跑）。
