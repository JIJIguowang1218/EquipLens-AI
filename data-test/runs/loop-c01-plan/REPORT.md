# C01 在线规划 + 引用核验 + 排序 · 12 槽（2026-11-10）

## 输入

- 任务单：`brief-m1-desert.json`
- 部件（按要求改为）：**防护栏 / 大灯 / 前轮拱 / 登车踏步**（+ 区域“前脸”，区域不参与验收）
- 车槽：12（exact 8 + environment 4）
- 候选：`plan-c01/plan.json`（DeepSeek Search 4 查询 → 27 条结果 → LLM 抽取 16 候选，0 条因无效引用被丢）

## 新增的两个环节

### 引用核验（citation check）

对每条候选的引用页调 `POST /v1/tools/fetch`，检查页面标题/正文是否出现该车型的关键 token：

| 指标 | 值 |
|---|---:|
| 抓取引用页次数 | 18 |
| 匹配成功 | **10（56%）** |
| 未匹配 | 8 |
| 延迟 | 0.6–22 秒（首取冷启动 22s） |

未匹配不等于“候选是假的”，可能是页面正文没写全型号（例如只写“油田牵引车”），或 token 取得太长。它的作用是**排序**，不是一票否决。

### 排序

同一批候选按 `citation_ok` 优先、再按规划顺序进入检索。这一轮能看到效果：Zetros、MOL、KAMAZ 等有引用的排前面，HOWO、Arocs 排后面。

但**排序目前只影响顺序，不影响取舍**：这批 12 个候选全部被抓了一遍，所以最终结果由“能不能抓到图”决定，不是排序决定的。真正的排序取舍要等“候选池 > 槽位 + 只激活前 N 个”那版。

### 为什么只填了 8 台

**16 个候选里有 8 个“0 张图”**，不是门卫拒的，是检索根本没返回可用图：

| 候选 | 引用 | 图 | 原因 |
|---|---|---:|---|
| TAZ4922 6×6 油田专用全驱牵引车（沙漠型，白色涂装） | ✓ | 0 | 型号名太长，检索无结果 |
| DFV5253TSMGP6D 沙漠车（6×6，轴荷7t/18t…） | ✓ | 0 | 同上 |
| ND5250TSMZ04 沙漠车（6×6，国Ⅵ…） | ✓ | 0 | 同上 |
| HOWO 6×6 油田牵引车（…约斯特可翻转鞍座） | ✗ | 0 | 同上 |
| 6×6 交叉country 越野沙漠卡车（ISLE310-30…） | ✗ | 0 | 同上 |
| 沙漠牵引车（采购技术条件…） | ✓ | 0 | 不是具体车型 |
| 6×6 全轮驱动沙漠越野货运卡车底盘（…） | ✗ | 0 | 同上 |
| 6×6 油田沙漠重型牵引车（600马力…） | ✗ | 0 | 同上 |

**根因**：规划输出的是“带说明的长名字”，检索直接拿整串去搜，360 上搜不到。需要**归一化成短查询键**（品牌 + 车系/型号代码），例如：

```
TAZ4922 6×6 油田专用全驱牵引车（沙漠型，白色涂装）
  → 查询键 "TAZ4922" / "泰安五岳 TAZ4922 6x6"
```

### 通过的 8 台（含 3 台外国品牌）

Zetros 4051 AS、Arocs、MOL-Brec TB 800、KAMAZ、东风 DFV2223、东风 EQ2250AX、北奔 ND5250TSMZ04（部分）、6×6 沙漠卡车。

## 结论

1. **在线规划可用**：16 个候选全部带真实引用，外国品牌自然出现，不需要任何品牌表；
2. **引用核验可用**：56% 的引用页能直接匹配车型；未匹配的候选仍然保留，只影响排序；
3. **排序还没真正生效**：因为是一次性激活整批，没有“只激活前 N 个”；
4. **主要瓶颈变成“候选名 → 检索键”的归一化**：8/16 的 0 图都是长名字导致；
5. **图仍然偏小**：29 张过门卫里只有 3 张 ≥800，来源多为经销商页。
